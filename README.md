# ND287 分割測定アプリ

HEIDENHAIN ND287（デジタル表示器）からRS-232Cで角度を読み取り、回転テーブルの
分割精度（割出精度）を測定・表示するデスクトップアプリ。
LabVIEW製「IK220分割測定」系アプリのPython移植版。

## 測定モード（画面左上で切替）

| モード | 内容 |
|---|---|
| 回転分割 | ホイール一周360°（閉じ点込み）を指定ピッチでCW→CCW ＋ ウォームCW→CCW |
| 傾斜分割 | 開始角度〜終了角度（例 −30°〜+110°）を指定ピッチでCW→CCW ＋ ウォーム |
| 回転再現性 | 再現開始・再現終了・ブロック数で測定位置を指定（例 開始0/終了270/4箇所 → 0,90,180,270）。各ブロックでCW×設定回数→CCW×設定回数。ブロックごとの最大−最小の最大が再現性の結果 |
| 傾斜再現性 | 同上（開始〜終了角度の範囲をブロック数で等分割、両端含む） |

- 取込中は **中止** ボタンでいつでもキャンセルできる（取込済みデータは破棄）
- 取込中にモードを切り替えた場合も取込はキャンセルされる

## 測定内容（分割モード）

- **ホイール**: 測定範囲を指定ピッチ（例 10°ごと）で割り出し、CW→CCW
- **ウォーム**: ウォーム1回転ぶんの角度範囲を指定ピッチで刻み、CW→CCW

### 操作の流れ

1. **型式・機番・日付・名前・測定温度**を入力し、各種等分数を確認して **取込開始**。
   必須項目が揃っていないと取込は始まらない（不足項目を警告表示）
2. データ受け取り状態になり、等分数ぶんの「箱」が用意される。テーブルを割り出して
   静止し、**ND287のPRINTキー（またはX41トリガ）で値を送る**と送られてきた順に
   箱へ入る。PC側から取りに行く **手動取込** ボタンも使える
3. 箱が全部埋まると、結果が自動で表示される
4. 必要なら**バックラッシ手動補正**（下記）と**コメント**を入力
5. **セーブ** で保存（保存先ルールは下記）。**ロード** で過去の測定を読み戻して
   グラフ・結果を再表示できる

### バックラッシ手動補正

測定結果と実際のメカ的な隙間に差がある場合、調べた差分（測定結果に対して
何秒多いか「+」少ないか「−」）を入力して **補正適用** を押すと、
ホイール・ウォーム両方のバックラッシMIN/MAXに加算され、温度別の合否判定も
補正後の値で再計算される。適用した補正値は結果表に「バックラッシ手動補正」
として表示され、セーブにも含まれる（ロードで復元）。生データ・偏差グラフ・
真の最大最小には影響しない。

### コメント

自由記入欄。セーブでCSVに保存され、ロードで復元される。

### 再現性モードの結果

- 左表: ブロックごとの CW範囲・CCW範囲（読み値の最大−最小[秒]）
- 右表: 再現性 CW / CCW（全ブロック最大）と総合
- グラフ: 各ブロックの読み値のばらつきを散布図で表示
- CSVの保存・ロードも分割モードと同じ操作（測定モードはファイルから自動判別）

### 旧形式（.BS）との互換

- 分割測定のセーブ時、CSVに加えて**旧LabVIEWアプリ互換の .BS** を
  `.BS保存先`（設定画面で変更可、既定 `K:\工機部内\共用\システム\検査表\データ`）に
  `<機番>.BS` で保存する（空欄にすると.BSは書かない）
- ロードは `.csv` と `.BS` の両方に対応。`.BS` を開くと型式・機番（ファイル名）・
  測定者・温度・刻みを復元し、結果を再計算して表示する
- .BSのデータ行（1行 = 指令角度 + CW測定値の度分秒 + CCW測定値の度分秒）は
  実物ファイルとの**バイト一致の読み書き**をテストで保証
- ヘッダの「間隔/1/N/点数」は等価な別表現（例 30°×1/3 → 10°×1）で書くため、
  旧アプリでのロード確認を一度行うこと

### 旧形式（.KS・傾斜分割）との互換

- ロードは `.KS` にも対応。傾斜分割モードに自動で切り替わり、測定範囲・
  評価範囲1・型式・測定者を復元して再計算する
- 傾斜分割は**任意誤差評価**: 精度 = ホイール精度（素のPP）＋ ウォーム精度
  （傾き補正後PP）を正・逆それぞれで算出。実物261166ITY.KSで旧アプリ表示と
  全12値一致を確認済み
- **評価範囲1/2**（客先要求の部分抜き出し評価）: 画面のチェックと開始/終了角度で
  指定し、範囲内のホイール精度＋ウォーム精度を表示
- 傾斜分割ではバックラッシの合否判定をしない（MIN/MAXの表示のみ。旧アプリと同じ）
- **保存**: 傾斜分割のセーブ時、CSVに加えて `<機番>.KS` を `.BS保存先` と同じ
  フォルダに書き出す。精度行は旧アプリと同一の計算（全18値一致を確認）、
  データ行は実物とバイト一致。ヘッダのMAX/MIN行はバックラッシの最大/最小
  （端点補正後）を書くが、旧アプリの補正状態によっては値が異なることがある

### 保存ルール

- 保存先ルートは設定画面（settings.json）で指定
- 型式の系列フォルダを自動作成し、機番がファイル名になる
  - 例: 型式「RWE-200」機番「12345」 → `<保存先>/RWE/12345.csv`
- CSVには型式・機番・測定条件・生データ・結果サマリが全部入り、
  ロード時は生データから結果を再計算して表示する

### 画面に出る結果

系列ごと（ホイールCW / CCW、ウォームCW / CCW の4系列）。表のホイール／ウォーム
それぞれの先頭に**規格行**が入り、規格を超えた値は赤字になる:

| 項目 | 内容 | 規格 |
|---|---|---|
| 精度PP | 偏差（測定値−指令値）の最大−最小 [秒] | 型式.csv（規格値）取込後に表示。未取込は「—」 |
| 単一誤差 | その点から次の点へ移ったときに発生した誤差の最大 [秒] | **≦5"（全型式統一）** |
| 隣接誤差 | 連続する2つの単一誤差が逆向きに重なってできる突起の最大 [秒]。例: ある点への移動誤差が+4"、次の点への移動誤差が−6"なら、合わせて10"の突起 → 隣接誤差10" | **≦10"（全型式統一）** |
| 傾き | 開始角度と終了角度の偏差の差 [秒]。一周して本来戻ってくるはずの位置に戻ってこなかったぶん。ホイールは閉じ点360°まで測定する | 合否判定.csv の 傾きH / 傾きW |

#### 補正前／補正後の切替

グラフ上の **「補正前（生データ）」「補正後（傾き補正）」** ボタンで表示を切り替える。
補正後は、各系列の**始点と終点の偏差を一致させた（傾き成分を除いた）**偏差・精度を
表示する。生データを見たいときは補正前にする。

※ピッチエラー補正（提出用のP補正）はこの切替には**含めない**。明示的に選択した
ときだけ行う（印刷時に「ピッチエラー補正のページを付けますか？」と確認。既定は付けない）。

全体（コンパクトに1項目1行で表示）:

| 項目 | 内容 |
|---|---|
| ホイール／ウォーム／総合 バックラッシ | 同一指令角度での CCW偏差−CW偏差の MIN〜MAX に、**測定温度の規格**と OK / NG を併記。ホイールが合金製で熱膨張するため温度で規格が変わる |
| 真の最大最小 | ホイール偏差とウォーム偏差が最悪方向に重なった合成値（仮実装、下記参照）。CW/CCW合わせた最悪値で総合判定する |

### 温度別の合否規格

`settings.json` の `judgement_spec` で、項目ごと・温度帯ごとに規格を設定する:

```json
"judgement_spec": {
  "wheel_backlash": [
    { "temp_min": 0.0,  "temp_max": 15.0, "min": 0.0, "max": 30.0 },
    { "temp_min": 15.0, "temp_max": 25.0, "min": 0.0, "max": 25.0 },
    { "temp_min": 25.0, "temp_max": 40.0, "min": 0.0, "max": 20.0 }
  ],
  "worm_backlash": [
    { "temp_min": 0.0,  "temp_max": 15.0, "min": 0.0, "max": 20.0 },
    { "temp_min": 15.0, "temp_max": 25.0, "min": 0.0, "max": 15.0 },
    { "temp_min": 25.0, "temp_max": 40.0, "min": 0.0, "max": 12.0 }
  ],
  "true": [
    { "temp_min": 0.0,  "temp_max": 15.0, "min": -30.0, "max": 30.0 },
    { "temp_min": 15.0, "temp_max": 25.0, "min": -25.0, "max": 25.0 },
    { "temp_min": 25.0, "temp_max": 40.0, "min": -20.0, "max": 20.0 }
  ]
}
```

測定温度がどの温度帯にも該当しない場合は「判定不可」と表示される。
規格を空（`[]`）にした項目は判定しない。
**※初期値は仮の規格値。実際の温度別規格に合わせて書き換えること。**

## 起動方法（Windows・ダブルクリック）

| ファイル | 用途 |
|---|---|
| `ND287分割測定.bat` | 本番起動。初回だけ自動セットアップ（ライブラリのインストール）を行う |
| `ダミーで起動.bat` | 実機なしの疑似データで画面・操作を確認 |
| `exeを作る.bat` | Python無しの検査PCに配る単体exe（`dist\nd287_bunkatsu.exe`）を作る |

前提: PCにPython（3.10以降推奨）が入っていること。入っていなければバッチが
案内を出すので、https://www.python.org/downloads/ からインストール
（「Add python.exe to PATH」に必ずチェック）して再度ダブルクリック。
初回セットアップの1回だけインターネット接続が必要。2回目以降はオフラインで起動できる。

## 接続先プロファイル（X32 / X31 の切替）

画面右下の「接続先」プルダウンで **X32（USB直結）** と **X31（変換器経由）** を
切り替えられる。それぞれ別のポート・ボーレート・パリティを `settings.json` に
保持し、切り替えると自動で再接続する。古い型式（X31しか無い表示器）を測る
ときはX31に切り替えるだけ。

注意: ND287は測定値の出力先インターフェイスを1つしか選べないため、
本体側の INSTALLATION SETUP → インターフェイス設定 の出力先も合わせて
切り替えること。

## データ数表示

取込中は受信値の右に「データ数: ホイール CW 5/37 …」のように、系列ごとの
現在のデータ数／必要数を常時表示する（再現性モードでは CW/CCW の合計）。

## 型式マスタ（測定条件・合否判定の自動適用）

`マスタ/測定条件.csv` と `マスタ/合否判定.csv`（パスは settings.json の
conditions_csv / judgement_csv で変更可。K:の共有マスタを直接指すこともできる）。

**型式を入力すると自動で適用される:**

- 測定条件: ホイール刻み（間隔H÷N）・ウォーム刻みと範囲（間隔W÷N×分割数2）・
  測定順（HR/WR/WL/HL）
  - 測定順が0/空欄の系列は測定しない（例 RT-222はホイールのみ）
  - 合否判定マスタの歯数・モジュール等の列はP補正用のデータで測定条件には使わない
- バックラッシ規格（温度式）: **MIN = MINA×温度+MINB、MAX = MAXA×温度+MAXB**
  - 例 RWE-200 @26°C → 8.4〜46.2"。A欄が空の型式は温度に依らず一定（例 RBS-160: 5〜15"）
  - マスタに無い型式は settings.json の judgement_spec（規格帯）にフォールバック
- 傾き規格: 傾きH/W列と |傾き| を突き合わせて系列ごとにOK/NG表示
- バリエーションは「RB-250Ri」「RN-100N」のように連結した型式名で引ける

## 合体測定（分割＋再現を1回で）

モードに「回転分割+再現」「傾斜分割+再現」を追加。分割（ホイールCW一周→
CCW一周→ウォームCW/CCW）を測り終えてから、各ブロックで再現をN回測る——という
1つの流れ。受信順は FANUC合体プログラムの完了信号(M80)の発火順と完全一致する
（再現はCW読み→CCW読みを1サイクルずつ交互）。結果表には分割の全結果に加えて
再現性（ブロックごとのCW/CCW範囲・全ブロック最大・総合）が並ぶ。セーブは
分割CSV＋.BS/.KS、再現は `機番_再現.csv` に分けて保存。

## FANUC測定プログラム作成

「プログラム作成」ボタンで、現在の測定条件から測定用Gコードを生成する
（設定→プレビュー→.NC保存）。設定で変更できる:

- **割出軸**（既定 X）
- **前振り量（バックラッシュ消し）**: 各測定点へ片側から接近するための行き過ぎ量
- **ドゥエル（位置決め後の待ち）**: G04 X… 秒指定（小数点付きで秒）
- **完了信号Mコード**: ドゥエル後にカウンターへ送る（既定 M80。これでND287が値を取り込む）
- **再現をサブプロにする / 1本に展開**: ありなら再現は `M98 P… L{回数}` 呼び、
  サブプロ本体は現場の実物と同形（±前振りでCW読み・CCW読みの2点・M99）

- **カウンターリセット**: 分割を含むプログラムの先頭に、0°でバックラッシュを
  消す動作（G91 G00 X+p / X-p / X-p / X+p）＋ **M00**（一時停止）を入れる。
  作業者は止まった0°でカウンターを0にリセットしてからサイクル再開する
  （ON/OFF切替可）。傾斜では0°でリセット後に測定開始角へ移動する

分割は各パスの先頭で1回前振りし、以降はピッチ送り＋ドゥエル＋完了信号
（CWは負側・CCWは正側から接近）。合体測定モードでは分割＋再現を1本の
プログラムに合体生成する。**生成プログラムの完了信号発火数＝アプリの測定
シーケンス長**が一致することをテストで保証している。

プレビューは「**編集**」ボタンで手直しできる（その場で数行だけ直したいとき用）。
編集中は設定を変えても上書きされず、**保存(.NC)はプレビューの内容**をそのまま
書き出す。「プレビュー更新」を押すと設定から作り直す（手編集は破棄）。

## 条件の登録/編集（回転・傾斜・再現を分離）

「条件編集」ボタンで測定条件マスタを型式ごとに編集できる。ダイアログ上部の
「対象」で4種類を切り替える（それぞれ別ファイルなので条件が混ざらない）:

- **回転分割**: `マスタ/ユーザー回転条件.csv`（ホイール刻み・ウォーム…）。提供CSVより優先
- **傾斜分割**: `マスタ/ユーザー傾斜条件.csv`（開始/終了角度・刻み・ウォーム…）
- **回転再現**: `マスタ/ユーザー回転再現条件.csv`（ブロック数・回数・再現開始/終了）
- **傾斜再現**: `マスタ/ユーザー傾斜再現条件.csv`（同上）

「現在の画面条件で登録/更新」で今の値をその型式に登録、行クリックで画面に
読み込み、選択削除も可。型式を入れると、分割系では分割条件、再現/合体では
再現条件が、それぞれ対応する型式マスタから自動で入ります。

**重要（誤用防止）**: 傾斜分割モードで型式を入れても、**回転分割用の条件・
温度規格は一切参照しません**（傾斜専用マスタのみ）。傾斜で未登録の型式は
手入力になり、上で登録すれば次回から自動で入ります。回転と傾斜の条件が
混ざることはありません（テストで固定）。

## 過去データ検索（.BS/.KS）

「過去データ」ボタンで、**型式・機番を入れて .BS/.KS（検査表）フォルダを検索**する。
検索先は設定の「.BS/.KS保存先」。型式の頭文字フォルダ（例 RWE）や機番（ファイル名）
から探す。一覧には日付・型式・機番・名前・モードと、**保存済みの結果値**（ホイール
CW/CCW 精度・ウォームCW/CCW 精度・総合バックラッシ MIN/MAX/差）が出る。
これらは**旧アプリが保存した値そのまま**なので旧アプリと一致する。行をダブルクリック
（または「選択をロード」）でそのデータを読み込んで本画面に再表示。「CSV出力」で
検索結果一覧をCSV（Excelで開ける cp932）に保存できる。横断比較は「分析」へ。

## 分析（横断比較・1件詳細をグラフ/CSV/Excel/印刷）

「分析」ボタンで分析画面を開く。2つのタブがある:

- **横断比較**: **.BS/.KS（検査表）フォルダを型式・機番で検索**し（型式の頭文字
  フォルダ例 RWE から探す）、各系列の精度・傾き・総合バックラッシ等を
  1行=1測定の表にして並べる。値は旧アプリが保存した結果をそのまま使う。
  「グラフ指標」で選んだ指標をグラフ化でき、
  **横軸（機番／日付／型式）・集計（個別／平均／最大／最小）・グラフ種類（棒／折れ線）**を
  切り替えられる。例: 横軸=日付・集計=個別・折れ線で推移、横軸=型式・集計=平均・棒で
  型式ごとの平均。Excel出力のグラフもこの選択に従う。
- **1件詳細**: いま画面に表示中（取込またはロード済み）の測定を、大きい偏差グラフと
  全指標の表でまとめて見る。

どちらのタブも下のボタンで出力できる:

- **CSV出力** … 表をCSV（Excelで開ける cp932）で保存
- **Excel出力** … 表＋グラフ入りの `.xlsx` を生成（横断比較は棒グラフ、1件詳細は
  「指標」シートと、偏差を折れ線グラフにした「偏差」シート。グラフはExcelで編集可能）
- **印刷** … 横断比較はグラフ＋表をA4横で印刷。1件詳細は通常の検査記録（A4横）を印刷

Excel出力には `openpyxl` が要る（`requirements.txt` に同梱。exe化時もバンドルされる）。

## 主点評価（任意の等分数で評価し直し）

測定の等分数より粗い格子で精度を評価し直せる（例: 72等分で測定→12等分で評価）。
画面の「主点評価」に等分数を入れると、ホイールCW/CCWの主点精度が結果表に出る
（測定等分数を割り切れる値のみ）。旧アプリの精度1（1/Nの主点評価）と同じ計算で、
260976K（36等分測定）を12等分評価すると精度1と同じ7.5"/5.0"になる。

## 印刷（A4横・グラフ主役の検査記録）

「印刷」ボタンでA4横の検査記録を印刷できる（プリンタ選択ダイアログ。
Microsoft Print to PDFでPDF化も可）:

- 1ページ目: 型式・機番・測定日・測定者・温度・測定条件のヘッダ、
  **ホイールとウォームのグラフを7:3で隣り合わせ**（ページの主役）、
  系列ごとの精度表、バックラッシ・判定・主点評価・任意誤差などの全結果
グラフは白背景・濃い軸で描く（黒背景だと印刷で黒インクを大量に消費するため）。

- 2ページ目は印刷時に確認したときだけ付く（後述のピッチエラー補正を参照）


## ピッチエラー補正（提出用）

上部ツールバーの「**ピッチエラー補正**」ボタンで専用ダイアログを開く（回転/傾斜分割の
ホイール測定データがあるとき）。ピッチエラー補正は自動では行わず、ここで明示的に操作する:

- **補正表**: No・角度[°]・CW偏差["]・CCW偏差["]・平均["]・補正値（補正単位の整数倍）
- **補正前（破線）／補正後（実線）のホイール偏差グラフ**を重ねて表示
- **補正間隔・補正単位**をその場で変更（「この間隔/単位を既定にする」で settings.json の
  p_interval/p_unit に保存。既定10°・0.001°）
- **CSV保存**（型式・機番・間隔・単位のヘッダ付き）と**印刷**（提出用）

補正値はCW/CCW平均偏差を打ち消す向きに単位量子化。客先（FANUC・キタムラ等）の提出
フォーマット（符号・採用偏差・体裁）は見本に合わせて要調整。検査記録の印刷でも
「ピッチエラー補正のページも付けますか？」で同じ補正ページを添付できる。


## 生データ表示と管理者編集

「生データ」ボタンで測定値の数値一覧（系列・指令角度・測定値・度分秒・偏差）を
表示できる。通常は表示のみ。**ダイアログ内で Ctrl+Shift+E** を押して
管理者パスワード（settings.json の admin_password）を入れると測定値[°]列が
編集可能になり、「編集を適用」でグラフ・結果が再計算される。

## 自動測定（XR20監視ツールの移植・SwitchBot連携）

app526リポジトリの xr20_tool（旧LabVIEWアプリを画面OCRで監視して自動再測定する
ツール）の状態機械を移植した。新アプリはデータを直接持っているため画面読み取りは
不要になり、本質部分だけを統合している:

- **自動測定ボタン**: 取込開始 → SwitchBot Bot（物理ボタン押しロボット）で機械の
  起動ボタンを押す → 測定完了 → **傾き判定**（マスタの傾きH/W規格）→
  NGなら**自動で再取込＋再起動**（auto_max_retries回まで、既定2回）
- SwitchBot Botは **BLE直結**（PCのBluetoothから直接、ハブ不要、要 pip install bleak）で押す。
  旧 xr20_tool と同じBLEプロトコル（書込特性 `cba20002-…`、payload `57 01 00`、
  パスワード時はCRC32）。押し方（1回押し/2回押し（5秒/3秒間隔）/3回押し）も選べる
- SwitchBot未設定でも自動測定は動く（物理押下だけスキップ＝機械は手動起動）
- 中止ボタンで自動測定も停止

**設定は「設定」画面の「自動測定（SwitchBot Bot・BLE直結）」欄**で行う：
Bot BLE MAC（**「スキャン」ボタンで近くのSwitchBotをBLE自動検出して選べる**＝手入力不要、
旧 xr20_tool と同じ検出方法・サービスUUID 0000fd3d）・BLEパスワード・押し方・
自動再測定の上限・押下までの待ち。

## Webモニタ（離れたPCから閲覧・再測定指示）

settings.json で `web_enabled: true` にすると、アプリ内にWebモニタが起動する。
同じLAN内のPC・タブレットのブラウザで `http://<測定PCのIP>:8765/` を開くと:

- **測定状態**（待機中／測定中 n/96／測定完了）と型式・機番・温度が2秒ごとに自動更新
- **グラフと全結果**（精度・バックラッシ・判定。NGは赤字）を閲覧
- **「再測定指示」ボタン** → 現場のアプリが自動測定を開始
  （取込中なら破棄して再開。SwitchBotが設定済みなら機械の起動ボタンも物理押下）

設定: `web_port`（既定8765）、`web_token`（設定すると
`http://…:8765/?token=○○` のようにtoken付きアクセスのみ許可）。
社内LAN内での利用前提。測定PCのWindowsファイアウォールで該当ポートの
受信許可が必要になる場合がある。

## product-inspection（Webアプリ）連携

settings.json で `webapp_sync_enabled: true` にすると、**セーブ時に測定結果を
product-inspection の Firebase（Firestore）へ自動送信**する。送信内容は
型式・機番・測定者・温度・モード・全結果行・総合判定（NGが1つでもあればNG）・
グラフ画像。Web側は同じFirestoreをリアルタイム購読するだけで一覧・詳細表示
できる（貼るだけの閲覧コンポーネントを `docs/product-inspection連携.md` に同梱）。
実機のFirebaseに対して書込→読出→削除のE2E検証済み。

## 時間取り連動（product-inspectionの作業計測と連動）

product-inspection の時間取りと Firestore 経由で連動する（`webapp_commands_enabled`
と `webapp_station` を設定）:

- **準備タイマー開始** → アプリが前面化し、型式・機番・モードを自動セット
  （マスタ自動適用）して取込待ちに
- **測定タイマー開始** → 自動測定を開始（SwitchBot ON なら無人でNCスタート）
- **測定完了** → 完了イベント（総合判定つき）をWebへ返し、測定タイマーを自動終了

宛先は **ステーションID**（各PCに1個）で分離するので、7台あっても自分宛の指令
だけ実行する。詳細・Web側の組込み手順は `docs/product-inspection連携.md`。
実機Firebaseで 準備→測定→完了 の往復をE2E検証済み。

## COMポートの自動検出

起動時に全シリアルポートを順に探索し、CTRL B を送って角度応答が返った
ポートをND287と判定して自動接続する。どのCOM番号に挿しても操作は不要。
接続状態は画面下のステータスバーに表示され、ケーブルを挿し直したときは
「再接続」ボタンで再探索できる。

注意点:
- 探索はND287本体のボーレート設定とPC側（既定 9600 8E1）が一致している前提。
  本体設定が違う場合は `--baud` `--parity` を指定する
- 探索中、各ポートに1バイト（CTRL B）を送信する。ND287以外のシリアル機器が
  同じPCにつながっている環境では `--port COM3` のように明示指定が安全

## コマンドラインでの実行

```
pip install -r requirements.txt

python -m nd287_app                          # 実機接続（COMポート自動検出、9600 8E1）
python -m nd287_app --dummy                  # 実機なしで画面・流れを確認
python -m nd287_app --port COM3              # ポート明示指定
python -m nd287_app --port COM3 --baud 19200 --parity N
python -m nd287_app --wheel-pitch 10 --worm-pitch 0.5 --worm-range 5
```

ホイール刻み・ウォーム刻み・ウォーム範囲・ウォーム開始角度は画面上でも変更できる。
測定完了後「CSV保存」で生データと結果サマリをCSV（Shift-JIS、Excelでそのまま開ける）に保存。

## 接続できないときのトラブルシューティング

まず画面右下の「通信診断」を実行する。全ポート×複数ボーレートで現在値要求を送り、
生の応答まで表示するので、結果は3パターンに分かれる:

1. **「シリアルポートが1つも見つかりません」** → PC側の問題。
   デバイスマネージャーの「ポート(COMとLPT)」にCOMが出ているか確認。
   出ていなければ変換器/ドライバの問題
2. **ポートはあるが全部「応答なし」** → 配線かND287側の設定
3. **受信はあるが「角度として解釈不可」** → 受信バイトの内容を開発側へ

### X31（D-sub 9ピン RS-232C）＋USB-シリアル変換器の場合

- 変換器のドライバ（FTDI / Prolific / CH340等）が入っているか
- **ケーブルはクロス結線（ヌルモデム）が必要**（TXD/RXDの2-3クロス＋5 GND）。
  ストレートケーブルだと全ボーレートで「応答なし」になる
- ND287本体の INSTALLATION SETUP → インターフェース設定 のボーレート等を確認
  （診断は複数ボーレートを試すので、不一致なら★付きで正しい設定が見つかるはず）

### FTDI変換器が「コード39（正しくないイメージ）」で動かない場合

デバイスマネージャーで「USB Serial Converter」に⚠が付き、プロパティに
「ドライバーを読み込むことができません（コード39）{正しくないイメージ}」と
出る場合は、PC側のFTDIドライバの破損（または古いドライバがWindows 11の
メモリ整合性にブロックされている）。

1. デバイスマネージャーで「USB Serial Converter」を右クリック → デバイスのアンインストール
   （**「このデバイスのドライバーを削除しようとしました」にチェック**して削除）
2. 変換器をUSBから抜く
3. FTDI公式（ftdichip.com → Drivers → VCP Drivers）の Windows用 setup executable
   最新版を管理者として実行でインストール
4. 挿し直して「ポート(COMとLPT)」に「USB Serial Port (COMx)」が出れば成功 → 通信診断へ

直らない場合は Windowsセキュリティ → デバイス セキュリティ → コア分離 →
メモリ整合性 を確認（管理されたPCは情シスに依頼）。

### X32（USB直結）の場合

- 仮想COMポートのドライバが必要。デバイスマネージャーにCOMとして出ていれば、
  X31と同じ手順（通信診断→設定）で使える

## ND287 実機接続前のチェック

1. ND287本体の INSTALLATION SETUP でボーレート／パリティを確認し、`--baud` `--parity` をPC側で合わせる（既定 9600 / E）
2. 角度表示は DEG（十進度）/ 度分秒（DMS）どちらでも受信可（自動判別）
3. ケーブルは X31（RS-232C）に接続

通信仕様: 現在値要求 = CTRL B (0x02) 送信 → ASCII 1行（CR/LF終端）で表示値が返る。
ACK (0x06) は受信時に自動除去。

## 未確定事項（実機・現場での裏取りが必要）

- **温度別の合否規格値**: `judgement_spec`（ホイール/ウォーム/総合）の初期値は仮置き。
  実際の規格表をもらえれば確定できる。
- **真の最大最小の合成式**: 現在は「ホイール偏差の最大＋ウォーム偏差の最大」（最小も同様）の
  単純合成。現場の計算と違う場合は `analysis.py` の `true_min_max()` だけ差し替える。
- **シリアル設定値**: ND287本体のメニュー設定値に合わせて `--baud` `--parity` で調整。
- **応答フォーマットの最終確認**: 本体出力設定によって桁数・単位記号が変わるため、
  実機で1行受信して `parse_angle()` の結果を確認するのが確実。
- **合否判定マスタ（AAA合否判定.csv 等）との連動**: 元アプリのCSVマスタを
  リポジトリに入れてもらえれば判定機能を追加できる。
