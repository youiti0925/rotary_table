# FANUC制御装置との直接通信 — 実現可能性の検討（相談メモ）

「ファナック制御装置に自動でパラメータを送る／プログラムを送る／プログラムを起動する」
ができるか、の検討。**まだ実装はしていない**。可否と前提・リスク・段階導入の整理。

> 注: 確定可否は対象機械の **CNC型式と搭載オプション** で決まる。そこが未確認なので、
> 本メモは「一般的にどうか」までの結論。最後の「確定に必要な情報」を埋めれば具体化できる。

## 結論（先に）

- **プログラム送信（PC→CNC）／状態・位置・パラメータの読取**は、CNCに
  **Ethernet + FOCASオプション**があればPCから自動でできる。技術的に十分可能で低〜中リスク。
- **パラメータの書き込み**は技術的には可能だが、書込許可(PWE=1)や電源再投入が要る項目があり、
  校正値を壊すと品質・安全に直結する＝**ハイリスク**。慎重に。
- **プログラムの自動起動（サイクルスタート）**は、安全上の理由でFOCASから直接の
  “サイクルスタート”は基本できない。やるなら (a) **DNC運転**でPCから流す、
  (b) 機械メーカーがPMC信号にスタートを割り当てていれば**PMC信号を叩く**、のどちらか。
  (b)は機械固有かつ安全管理が必須。
- 現状アプリは既に **SwitchBotで物理スタートボタンを押す**仕組みを持っており、これが
  “遠隔起動”の現実的な代替として機能している。FOCAS/DNC起動はその上位互換だが、
  オプションと安全承認が揃ってから。

## 通信手段の整理

### A. FOCAS2（FANUC純正API, `Fwlib32.dll`）
PCからCNCを操作する標準ライブラリ。できること:
- パラメータ read/write … `cnc_rdparam` / `cnc_wrparam`
- プログラム download(PC→CNC)/upload(CNC→PC) … `cnc_dwnstart4`/`cnc_download4`/`cnc_dwnend4`、`cnc_upstart4`…
- 実行プログラムの検索・選択 … `cnc_search` / `cnc_setpath`
- 位置・運転状態・アラーム読取 … `cnc_rdposition` / `cnc_statinfo` / `cnc_rdalmmsg`
- PMC信号 read/write … `pmc_rdpmcrng` / `pmc_wrpmcrng`

前提:
- CNCに **FOCAS2 / Ethernet（内蔵Ethernet または Data Server）オプション**（有償・発注時付与）
- **`Fwlib32.dll`**（FANUC配布。登録/ライセンスが要る。機械メーカー経由で入手することも多い）
- 接続は Ethernet（CNCのIPへTCP接続）。古い機械は HSSB ボード経由のことも
- Pythonからは ctypes で `Fwlib32.dll` を呼ぶ（コミュニティ製ラッパー `pyfocas` 等あり）。
  DLLは32bit想定なので実行環境のbit数に注意

### B. FTP / Data Server（プログラム転送だけなら軽い）
- Data Serverオプションがあれば、CNCがFTPサーバ/クライアントになり、
  **PCからプログラムをFTPで置く → 操作者が選んで起動**。FOCASより導入が軽く、転送だけなら有力。

### C. RS-232C / CF・USB（昔ながら）
- Ethernetオプションが無い機械は、RS-232Cやメモリカードでの転送が現実解。自動化はしにくい。

## 機能ごとの可否まとめ

| やりたいこと | 可否 | 手段 | 注意 |
|---|---|---|---|
| プログラム送信(PC→CNC) | ◯ | FOCAS download / FTP | EDITモード等の条件あり |
| 次に動かすプログラム番号の選択 | ◯ | `cnc_search` | |
| パラメータ読取 | ◯ | `cnc_rdparam` | 安全。監視に有用 |
| パラメータ書込 | △ | `cnc_wrparam` | PWE=1必須・電源再投入が要る項目も・**事故りやすい** |
| 状態・位置・アラーム読取 | ◯ | FOCAS各種 | 安全 |
| プログラム自動起動（サイクルスタート） | ✕〜△ | DNC運転 / PMC信号(メーカー次第) | **安全管理必須**。無人起動は要社内承認 |

## リスク・注意

- **パラメータ書込**: バックラッシュ補正・原点・校正値などを壊すと品質/安全に直結。
  読取は安全、書込は厳重な確認とログ・バックアップ前提で。
- **遠隔サイクルスタート**: 人が居ない所で軸が動くリスク。多くの現場で禁止または要承認。
  やるなら安全装置・承認フロー・非常停止の確保とセット。
- **オプション/ライセンスのコスト**と、社内ネットワーク（PC↔CNCのIP到達性・セキュリティ）。

## 現状アプリとの関係 / 段階導入の提案

今アプリは `.NC` を生成して保存している（「プログラム作成」）。起動は SwitchBot物理押しを実装済み。
ここから低リスク順に:

1. **状態/位置の読取（FOCAS read系）** — 安全ですぐ価値。XR20監視の代わりに運転状態を直接見られる
2. **プログラム送信＋番号選択** — 生成した `.NC` をそのままCNCへ。USB手運びが消える（FOCAS download か FTP）
3. **パラメータ読取** — 必要なら。安全
4. **起動・パラメータ書込** — 安全装置・社内承認を固めてから。起動はまず DNC運転 or 既存のSwitchBot継続

## 確定に必要な情報（これが分かれば具体化できる）

1. 対象機械のCNC型式（例 0i-MF / 31i-B5 / 18i など）
2. Ethernet / FOCAS / Data Server オプションの有無
3. PCとCNCが社内LANで繋がるか（IP到達性・許可）
4. 遠隔でのパラメータ書込・サイクルスタートを社内ルール上やってよいか
5. `Fwlib32.dll` を入手できる立場か（FANUC登録 or 機械メーカー経由）
