# FOCAS 実機確認の記録と、これから作るものの要件

**記録日**: 2026-11-21〜22
**対象**: 試験装置の制御装置（192.168.1.1）＝ 号機23（31i-MA）とみられる（下記）
**この資料の目的**: FTP と FOCAS を実機で試して分かった事実と、利用者と決めた方針を残す。
別のセッション・別のPCで、同じ前提から続けられるようにする。

事実（実機で確かめた）と、推測・未確認は分けて書く（CLAUDE.md の決まり3）。

## 0. 結論（先に）

- **FTP（機械が取りに来る方式）は通った。** ログイン・一覧・読込（RETR）・送出（STOR）まで動いた。
  ただし機械の前で番号を入れて読込む操作は残るので、カードより大きく楽にはならない。
- **FOCAS（PCから直接）で、プログラムの読む・消す・書く、パラメータの読む・書くが全部できた。**
  機械の前での操作なしで、パラメータ変更とプログラム入れ替えをPCからできる道が通った。
- 方針（利用者と決定）: 作業の前に必ずバックアップ。FOCAS は「今の機械の値」を土台にする。
  当面は「書く → 読み戻して照合 → アラーム確認」まで。運転開始はPCからしない。

## 2. FTP（制御装置が取りに来る方式）で分かったこと

アプリの `ftpserver.py` をそのまま使い、ログをファイルに残して試した。

| 事実 | 内容 |
|---|---|
| 接続・ログイン | 機械は `USER CNC` / `PASS` で入ってくる。ログインは毎回通った（9bb75b3 の修正が効いている） |
| データ接続 | 機械は **PORT（アクティブ）** を使う。PASV は使わなかった。425 は一度も出なかった |
| 一覧 | 「デバイス変更」で一覧を取りに来る。`NLST` が主で、`LIST` も来る。毎回 226 で正常終了 |
| 一覧の形 | UNIX 形式・MS-DOS 形式（24時間）・IIS 形式（AM/PM）・データ接続を20番から、のどれでも機械の動きは同じだった |
| 読込（RETR） | 機械は **`RETR O0901` のように「O＋4桁・拡張子なし」** で取りに来る（`O8888` / `8888` も来た）。ファイル名に `.NC` を付けると見つからない |
| 送出（STOR） | 機械からの `STOR ALL-PROG.TXT`（全プログラム 4867B）を正常に受け取れた |
| 送出の区切り | **`LF` だけ**（`CR` なし）。カードの `LF CR CR` とは違う |
| 「フォルダ変更」 | ファイルを選んで押すと `CWD O0900` が来る（ファイルをフォルダとして開こうとする）。550 を返すので何も起きない。正常な動き |

- 作業者の目視では「一覧にファイル名が出ない」だったが、機械は `CWD O0902.NC` / `CWD O0900` と
  名前を指定してきた。一覧は機械に届いていた。画面にどう出ていたかは**未確認**（写真が無い）。
- `O0901` を `RETR` で渡したが、機械の一覧には増えなかった。あとで FOCAS で読むと
  **登録できる残り本数が 0** だった。読込が入らなかった原因はこれとみられる（ほぼ確実。機械の画面では見ていない）。
- 公開フォルダに試験用の別ファイルを混ぜると一覧に出る（作業用の `.claude` フォルダが出ていた）。

### 書き込み・削除（利用者の承認を得て実施）

| 操作 | 関数 | 結果 |
|---|---|---|
| プログラム削除（RT-85 フォルダの33本） | `cnc_pdf_del` | 33本全部消えた。登録 72→39、残り 0→33。事前に全部控え済み |
| プログラム書込（O0901 → PATH1） | `cnc_dwnstart4` / `cnc_download4` / `cnc_dwnend4` | O901 が増えた。読み戻しは送ったデータと1バイト一致 |

- 書込・削除は、すべて **機械がリセット状態（止まっている）** のときに行った。
- プログラムの書込は `LF` 区切り・先頭 `\n`・末尾 `%` で渡した。機械の中は `LF` で持つ。
  元ファイル（`LF CR CR`）との違いは改行だけで、各ブロックは同じ。

### パラメータの型コード（`cnc_rdparainfo` の prm_type。31i で実機照合）

| 例 | 型コード | 読み方 |
|---|---|---|
| 0000 | 16 | ビット |
| 0020 | 17 | バイト |
| 1020 | 5 | バイト・軸型 |
| 1815 | 68 | ビット・軸型 |
| 2165 | 6 | ワード・軸型 |
| 1821 | 71 | 2ワード・軸型 |
| 1320 / 1420 | 4103 | 実数・軸型 |

- 下位2ビット: 0=ビット 1=バイト 2=ワード 3=2ワード。`0x4`=軸型。`0x1000`=実数。
- `0x10` と `0x40` の意味は**未解読**。`0x40` は「電源再投入が要る」かと思ったが、
  1815 に付いて 1020 に付いていないので合わない。**再起動が要るかは、書いた後の PW0000 で判断する。**

### FOCAS で取ったパラメータの形（カードと違う）

- 区切りは `LF` だけ（カードは `LF CR CR`）。
- 実数は `P-1.0` と書く（カードの BASIC は `M`）。
- このため `param_origin.classify` は「PC製」と判定する。**中身は本物の機械の値。**
  → **FOCAS の控えを BASIC フォルダに入れない**（調査記録 §4 の前提が崩れる）。別の場所に置く。

### プログラムの枠

- 31i はフォルダで管理する（`//CNC_MEM/USER/PATH1/` ほか）。登録本数はプログラム＋フォルダの数とみられる
  （62本＋フォルダ9〜10個で72。ほぼ確実だが厳密には未確認）。
- 空き容量があっても、**本数の枠が0だと1本も入らない。**

### 共通変数

- バックアップ時点で **#500〜#999 は全部空き**。

## 4. 号機23 の「今の機械」と BASIC の違い

`F23BASIC.DAT`（2008年・カード由来）と、FOCAS で取った今の値を比べた。

- 共通にある 24483か所のうち **185か所（90番号）で値が違う**。
- 主なもの: 1420・1430（早送り。例 A4 4000→20000）、1425、1620〜1622、1821、1828、
  2000〜2211、14376〜14637（サーボ関係）、0000、0020、6753・6754（積算カウンタ）。
- **2008年の BASIC の後で、速度・サーボを再調整して使われている。**
  BASIC 基準で全部書き直すと、この調整も戻る。

### 調査記録 §3 の「181個」の訂正

- 調査記録 §3 は「号機23 の制御装置は N09802・N09820〜N09999 の181個を持っていない」とした。
- **FOCAS で読むと、この181個は機械にある。** 今の機械にあってカードの BASIC に無いのは、ちょうどこの181か所だった。
- 正しくは「**カードへのパンチアウトには出ない番号。機械には存在する**」。
- .prm に入っていると読めなかった理由が「存在しないから」ではないことになる。本当の理由は**未確認**
  （書込保護か、別の理由か）。.prm が読めなかったもう1つの原因（区切りが LF だけ）は記録どおり。

## 5. 利用者と決めた方針（2026-11-22）

1. **作業の前に、必ず制御装置のバックアップを取る。**
2. **FOCAS でつながる機械は、今の機械のパラメータを土台にして、製品の値だけ変える。**
   メモリカードの機械は、今までどおり BASIC を土台にする。
3. 機械の値が最初からおかしく、差し替えだけでは直らないときは、**BASIC 基準で書き直す。**
   ただし全部まとめて戻さず、違いを一覧で見せて、戻す番号を人が選ぶ（号機23 の例のように、再調整された値があるため）。
4. **当面の範囲は「書く → 読み戻して照合 → アラーム確認」まで。運転開始はPCからしない。**
5. 運転中・一時停止中・非常停止中・アラーム中は書かない。リセット状態のときだけ書く。
6. PWE の ON/OFF、電源の入れ直し、原点復帰、スタートボタンは人がやる。
   電源の入れ直しが要るときは、PW0000 を見て画面に出し、機械が戻ってきたら自動でつなぎ直して照合し直す。
7. 書込・削除は毎回、利用者本人の許可を取ってから。

## 6. これから作るもの（要件。順番は利用者と相談済みの案）

### ① FOCAS の基本
- 機械の読み取り（状態・アラーム・パラメータ・プログラム一覧）とバックアップ
- 製品の値を書く → 読み戻して照合 → アラーム確認（PW0000 なら再起動の案内と再照合）
- 測定プログラムを書く → 読み戻して照合 → 運転するプログラムとして選ぶ（選ぶのは未試験）
- 機種で関数が違う: 31i/35i はフォルダ（`cnc_pdf_*` / `*4`）、0i-D・18i は番号で扱う。機種ごとに「同じ値を書いて戻す」試験を1回ずつする

### ② 1周チェック（傾き）とカウンタのソフトゼロ合わせ
- 心配: 製品と測定機のカップリングがうまく付いていないと、一周して同じ位置に戻らず、測定が丸ごと無駄になる。
  今のアプリは傾きを**測り終わってから**判定している（`analysis.slope`、自動測定では傾きNGで再測定）。
- 案1（FOCASなし）: バックラッシ消し → カウンタ0 → 1周して戻る → M80 で読む → アプリが傾きの合格値で判定 → M00。OKなら人がスタート。
- 案2（FOCAS）: 1周して戻ったら、プログラムは共通変数（例 #900）で**アプリの返事を待つ**。アプリが判定して FOCAS で返事を書く（OK=続行、NG=プログラムが自分でアラームを出して止まる）。
  **返事が来ないまま決めた時間がたったら止まる（永遠に待たない）。** 離れた作業者に知らせる。
  運転中に FOCAS でマクロ変数を書けるかは**未確認**（止まっている状態での書込・読み戻しから試す）。
- 利用者の評価: 案1は作業者がそこまで見ないといけない。案2は将来ほかにも使えそうで面白い。
- カウンタのリセットを押し忘れても、アプリで「最初の 0° の読み」を基準に生データをずらせるようにする（標準で入れる）。
  生データは残し、ずらしたことと量を画面に出す（黙って直さない）。

### ③ アラームの記録と「どれで解決しましたか」
- アラームが出たら、日時・号機・型式・製番・アラーム番号と文言・そのときの状態とプログラム位置を自動で残す。
- 解決後に選択式で聞く。候補は `fanuc_alarms`（内蔵＋ユーザーCSV）と、これまで社内で記録された対処。
  「どれでもない（会社特有）」なら一言書いてもらう。会社特有の対処は情報として価値が高い。
- 書かれた対処は、次から同じアラームの候補の上に出す。

### ④ アプリ同士の情報共有（社内の使う人だけ）
- メッセージ・危険の知らせ・アラーム記録を共有したい。
- 今の `firestore_sync`（product-inspection）は**匿名認証で誰でも読み書きできる public の場所**なので、社内限定の情報には向かない。
- 案: 会社のファイルサーバーの共有フォルダを掲示板にする（Windows の権限で社内限定）。置き場所は会社で決める。

### ⑤ 組立モード
- 組立側も、パラメータとプログラムを機械へ入れる・アラームの対処をすぐ見る、が欲しい。
- 同じアプリの画面を絞ったモードにして、中身（FOCAS・パラメータ作成・アラーム検索）は共通にする。
