# はじめてモードを、アプリ全体に広げる設計（2026-11-25）

対象: ND287 分割測定アプリ（main 0ce0b2d）。**この資料は設計だけで、コードは変えていません。**

書き分け: **事実**＝コードを読んで確かめたこと（ファイルと行を書く）／**未確認**＝実機・実データで確かめていないこと／**案**＝この設計で決めたいこと。

---

## 0. 結論（先に）

1. **「どこでするのか分かりづらい」のは本当でした。** 測定条件は入口が3つ（入れる所・登録する所・自動で入る所）に分かれ、測定プログラムは作る所が4つあり、名前も中身（画面の値から作る／登録から作る）も別々です（§1）。
2. **はじめてモードには、いま行き止まりが1つあります（事実）。** 型式の測定条件が登録に無いと、機械に入れる手順の中で「測定プログラムは作れません」と出て止まり、登録する画面（条件編集）は、はじめてモードを開いている間は押せません（§1-4）。
3. 設計の中心は4つです。
   - ホームのタイルを 4 → 6 にする（**測り方を決める・登録する**／**使い方・ことばの説明** を足す）。
   - どの手順にも、同じ場所に3つのボタンを出す: **一旦やめる**／**アラーム（機械から読む）**／**？ことばの説明**。
   - 測定条件は「分割だけ・再現性だけ・両方」を絵で選び、要る欄だけを絵つきで入れ、**1回押すだけで登録**（次から同じ型式は自動で入る。これは今の仕組みのまま）。
   - アラームは **機械から読む → 意味とやること → 直ったか、もう一度読んで確かめる**。
4. 新しい決め方は作りません。全部、今ある関数を呼びます（§2 の表に、呼ぶ関数を書いています）。**機械に書くのは今までどおり、人が「書く」「送る」を押したときだけ**。PC から機械を止める・動かす・アラームを消すことはしません。
5. 作る量は、6段で **作業 7〜9 回ぶん**（1回＝1つの段を作って試験を全部通すまで）。一番大きいのは測定条件の段です（§4）。
6. **はじめてモードは、まだ一度も実機で通していません**（事実。`docs/はじめてモード_決めたやり方.md`）。今回足すものも同じです。実機で確かめることは §5 に 14 項目あります。

## 1. (a) 今の画面で、測定条件・測定プログラムはどこでするか（コードで確認した事実）

### 1-1. 測定条件 — 入口が3つ

| すること | 場所 | コード |
|---|---|---|
| **入れる** | 通常の画面の左「測定条件」の枠。モード（7種）・ホイール（刻み、傾斜は開始角度／終了角度）・ウォーム（刻み／範囲／開始）・再現（ブロック数／回数／再現開始／再現終了）・測定順 | `gui.py` 12862〜13004 行 |
| **登録する** | 上の並びのボタン **「条件編集」** → 窓の名前は「測定条件の登録/編集」。上の「対象」で 回転分割／傾斜分割／回転再現／傾斜再現 を切り替え、**「現在の画面条件で登録/更新」** を押すと、通常の画面に今入っている値がその型式で登録される | `b_cond` 13051 行 → `show_condition_editor` 13616 行 → `ConditionRegistryDialog` 11026 行 |
| **自動で入る** | 型式を入れたとき。分割は「自分で登録した条件 → 無ければ 会社の一覧（マスタ/測定条件.csv）」。傾斜は自分で登録した条件だけ。再現性は自分で登録した条件だけ | `on_model_entered` 13716 行・`_apply_division_conditions` 13753 行・`_apply_repeat_conditions` 13731 行 |

登録先は4つのファイル（回転と傾斜、分割と再現が混ざらないように別々）: `マスタ/ユーザー回転条件.csv`・`ユーザー傾斜条件.csv`・`ユーザー回転再現条件.csv`・`ユーザー傾斜再現条件.csv`。リポジトリの `マスタ` にはまだ無く、最初の登録で作られます。

分かりづらい所（事実）:

- **ボタンの名前と窓の名前が違う**（「条件編集」と「測定条件の登録/編集」）。
- 登録は「**先に通常の画面に値を入れてから**、条件編集を開いて押す」順番。窓の中では値を打てない（表は見るだけ）。
- モードが「分割+再現」のとき、条件編集は**再現のほうを最初に選んで開く**（13618 行）。分割も登録するには「対象」を切り替えて**もう1回押す**必要がある。画面にその説明は無い。
- 各欄（刻み・範囲・ブロック数など）が**何を意味するか**の説明は、画面に無い（ヘルプの文章だけ）。
- 会社の一覧（測定条件.csv）を直す画面は、アプリの中に無い（見た範囲では、`ConditionRegistryDialog` が扱うのは上の4ファイルだけ）。
- **回転の分割を自分で登録すると、会社の一覧より先に使われ、そのとき「測定順」は標準にもどり、主点評価の等分数は自動で入らなくなる**（13780〜13791 行。`self.master_cond = None  # ユーザー登録は測定順なし＝既定順`）。画面にこの注意は無い。

### 1-2. 測定プログラム — 作る所が4つ

| # | 入口 | 何から作るか | 出し先 | コード |
|---|---|---|---|---|
| 1 | ツール ▾ →「プログラム作成…」 | **通常の画面に今入っている値**（登録は見ない） | ファイル（.NC）／フォルダ・メモリカード／機械へ直接 | `show_program_dialog` 16196 行 → `ProgramDialog` 907 行 |
| 2 | ツール ▾ →「型式ごとに一括作成…」 | 会社の一覧（測定条件.csv）の全型式 | ファイルだけ | `BatchProgramDialog` 12203 行・`batch_build.batch_programs` |
| 3 | ツール ▾ →「**パラメータ…**」→ かんたん作成の4段目「測定プログラムを送る」 | **登録**（自分の登録 → 会社の一覧。傾斜は自分の登録だけ） | 機械へ直接 | `_build_program_panel` 8297 行・`wizard_programs.make_plan` |
| 4 | はじめてモード →「測る」／「プログラムだけ機械に入れる」 | 3 と同じ（かんたん作成を中に入れている） | 機械へ直接 | `easy_mode._open_wizard_inside` 953 行 |

分かりづらい所（事実）:

- 3 の入口の名前は「パラメータ…」で、**測定プログラムも入ることが名前から分からない**。
- 1 は「画面の値」、3・4 は「登録」から作る。**同じ型式でも、登録していなければ 1 では作れて 3・4 では作れない。**
- 1 の窓は、割出軸・前振り量・待ち時間・完了信号・クランプ・番号・改行の形式など、専門の設定が 20 以上並ぶ（907〜1090 行）。

### 1-3. はじめてモードの中では

- 測定条件を入れる・登録する手順は**ありません**。「機番・名前・温度を入れる」の手順に「型式と測り方は、もう入っています」と出るだけ（`easy_flow.py` 75 行）。入った値は見えません。
- 表示器（ND287）が PC につながっているかを確かめる手順も**ありません**（`easy_flow.py`・`easy_mode.py` に表示器の状態を見ている所が無い。通常の画面の帯は見ている: `flow_guide.py` 77 行）。

### 1-4. 行き止まり（事実）

型式の条件が登録に無いと、かんたん作成の4段目は「この型式の測定条件が見つかりません。測定プログラムは作れません。」で止まります（`wizard_programs.py` 209 行）。そこに登録へ進むボタンはありません。はじめてモードは `exec()` で開く窓（`gui.py` 14621 行）なので、開いている間は後ろの通常の画面の「条件編集」を押せません。**初心者は、はじめてモードを閉じて、通常の画面で値を入れ、条件編集で登録し、もう一度開き直す**ことになります。再現性の条件だけ無いときは、黙らずに「分割だけを作ります」と出ます（206 行）が、登録への道はやはりありません。

### 1-5. アラーム（事実）

- 通常の画面: ツール ▾ →「アラーム…」（`AlarmHelpDialog` 12527 行）。**番号かことばを打つだけ**。機械からは読まない。
- ツール ▾ →「機械と直接つなぐ（FOCAS）…」の窓には、機械から読んだアラームの表があり、選んで意味を調べられる（`FocasDialog.show_alarm_help` 2912 行）。**機械から読む仕組みは、もうある。**
- はじめてモード: 機械の様子を1秒ごとに読む係（`easy_machine.MachinePoller`）が、状態とアラーム（最大10件・番号と機械の画面の文字 32 バイトまで）を読んでいる（`focas_helper.cmd_alarms` 874 行）。ただしアラームの手順は「**最初の1件の番号を、開いたときに1回だけ欄に入れる**」だけ（`easy_mode._build_alarm` 662 行）。一覧・機械の文字・読み直し・「直ったか」はありません。
- アプリが持っているアラームの説明は **29 件**（`fanuc_alarms.BUILTIN_ALARMS`。ほかに利用者の CSV を足せる）。機械に出るアラームの多くは載っていません。
- 検索は番号の数字だけでも当てるので、**種類の違う番号が先に出ることがある**（試した結果: `PW0000` → 1件目が `PS0000`、`SW0100` → `PS0100`、`SV0436` → 0件）。はじめてモードは1件目だけを出す（683 行）。

### 1-6. 中止・戻る・保存（事実）

- 「もどる」は全部の手順にある。ただし**測っている途中に「もどる」を押すと、PC の取込は続いたまま前の手順にもどる**（`_back` 442 行は取込を止めない）。
- 取込の中止（通常の画面の「中止」`cancel` 13923 行）は、**確かめずに、測った値を全部捨てる**。途中の値を取っておく仕組みは無い（値はアプリを閉じると消える）。「1点戻る」（`undo` 15073 行）はある。
- PC の取込は「値が来るのを待つ」だけで、時間切れは無い（`sequence.py` に時間切れの処理なし）。機械が途中で止まっても、PC は待ち続ける。
- はじめてモードを閉じるときの確認は、測っている途中だけ（1036 行）。**測り終えて保存する前に閉じても、何も聞かれない。** 通常の画面を閉じるとき（16502 行）・もう一度「取込開始」を押したとき（14938 行）も、保存していない結果があるかは聞かれない。

## 2. (b) 画面の流れ

### 2-1. ホーム（タイル 4 → 6）

```
┌───────────────┬───────────────┬───────────────┐
│ 測る            │ 測り方を決める・  │ プログラムだけ    │
│ [はじめてはこれ]  │ 登録する  【新】  │ 機械に入れる     │
├───────────────┼───────────────┼───────────────┤
│ 結果を見る・印刷  │ アラームを調べる・ │ 使い方・ことばの  │
│                │ 直す    【広げる】 │ 説明     【新】  │
└───────────────┴───────────────┴───────────────┘
  下に1行:  表示器 ● つながっています ／ 機械 ● 見えています（23号機） ／ ▲ アラーム 1 件 ▶ 調べる
```

- タイルは今の最小 220×150。3列×2段で幅 700 ほどなので、1024×768 に収まる（試験 `TestDialogsFitOnSmallScreen` に追加して確かめる）。
- 下の1行は、もう読んでいる値を出すだけ（表示器＝`MainWindow._nd_ok`、機械＝`MachinePoller.state()`）。

### 2-2. どの手順にも出す3つ（上の章の帯の右）

```
 1 つなぐ ─ 2 製品を決める ─ …            [▲ アラーム 1件]  [？ことば]  [■ 一旦やめる]
```

| ボタン | 押すと | 元の手順へ |
|---|---|---|
| **アラーム**（無いときは灰色の「機械 ●」。出たら赤く「アラーム N 件」） | §2-5 のアラームの手順を、いまの手順の上に重ねて開く | 「もとの手順にもどる」で、重ねる前の手順へ |
| **？ことば** | いまの手順に関係することばのカード（§2-6）を1枚 | 「とじる」 |
| **一旦やめる** | §2-4 の「一旦やめる」の画面 | 「つづける」 |

作り: `EasyModeDialog` に「重ねた画面」を1つ持つ（`self.overlay`＝ pause／alarm／word）。重ねている間、下の手順・中に入れたかんたん作成・取込は**そのまま生かしておく**（片づけない）。

### 2-3. 測定条件（要望 1・2）

#### 入口は3つ、中身は1つ

| 入口 | いつ |
|---|---|
| ホームの「測り方を決める・登録する」 | 前もって登録しておきたいとき |
| 「測る」の流れの **測る準備** の最初（新しい手順「測り方を確かめる」） | 毎回。登録があれば見るだけ・無ければ入れる |
| 機械に入れる手順の中で「測定条件が見つかりません」と出たとき（§1-4 の行き止まり） | 上の絵と短い言葉の所に **「測り方を決める ▶」** を出す。かんたん作成は開いたまま、重ねて開く。終わったら、かんたん作成に条件を読み直させて続きへ |

#### 手順（1画面に1つのこと）

| # | 画面 | 絵 | 入れるもの・出るもの | 呼ぶ既存の関数 |
|---|---|---|---|---|
| 1 | **型式** | 製品の銘板 | 型式（もう入っていれば出すだけ）。下に「分割: 登録あり（会社の一覧）／再現性: 登録なし」 | `wizard_programs.division_conditions`・`repeat_conditions`（今の引き方そのまま） |
| 2 | **何を測りますか** | 3つの絵のボタン | **分割だけ／再現性だけ／両方**。回転か傾斜かは、製品から分かるときは聞かない（`wizard_programs.decide_kind`）。分からないときだけ2つの絵で聞く | 選んだものを通常の画面のモードに入れる（`wizard_programs.MODE_FOR` と同じ対応。`mode_combo.setCurrentText` → `on_model_entered`） |
| 3 | **分割の条件**（分割だけ・両方のとき） | 円盤に目盛りの絵。刻みを変えると目盛りの数が変わる | 「何度ごとに測るか」（刻み）→ 絵の下に「360 ÷ 10 ＝ **36 か所**」。次に「細かく測る所」（ウォームの刻み・範囲・開始）。傾斜は「どこから・どこまで」（開始角度・終了角度）が先 | 欄は通常の画面の欄とつなぐ（`e_wheel`・`e_worm`・`e_range`・`e_start`・`e_wstart`・`e_wend`。今の「機番・名前・温度」の手順と同じつなぎ方） |
| 4 | **再現性の条件**（再現性だけ・両方のとき） | 円盤に止まる所の印。数を変えると印が動く | 「何か所で」（ブロック数）・「何回ずつ」（回数）・「どこから・どこまで」（再現開始・再現終了）→ 下に「**0°・90°・180°・270° の 4 か所 × 7 回**」 | `e_blocks`・`e_repeats`・`e_rstart`・`e_rend`。止まる所は `MainWindow.repeat_blocks()` の結果をそのまま描く |
| 5 | **登録する** | 型式の札が引き出しに入る絵 | 入れた値のまとめ。**「この型式で登録する」1回**で、要る分（分割・再現性）を全部登録。前の登録があれば「前 → 今回」を並べて出す | `masters.upsert_user_condition` ＋ `reload_masters`（条件編集の「現在の画面条件で登録/更新」と同じ中身。記録の作り方 `ConditionRegistryDialog._current_record` を `MainWindow` 側へ移して両方から呼ぶ） |
| 6 | **できました** | ✓ | 「次から、この型式を入れると自動で入ります」。ホームから来たときは「続けて、測定プログラムを機械に入れる ▶」（今の「プログラムだけ機械に入れる」の流れへ） | — |

各欄の入れ方: 1画面に欄は多くて4つ。欄を選ぶと、絵の中のその欄が表す所（目盛りの間・細かい区間・止まる所）が橙色になる。各欄の下に1行の説明と「ふつうの値」（登録や会社の一覧にある値。無ければ出さない。勝手な「おすすめ」は作らない）。

#### 守ること（§1-1 の事実から）

- **会社の一覧から入った値を変えていないときは、自分の登録を作らない。**「もう登録されています（会社の一覧）」と出して終わり。作ると、測定順と主点評価が自動で入らなくなるため。
- 会社の一覧にある型式で値を変えたときは、登録の前に1行出す: 「これからは、あなたの登録を先に使います。測る順番は標準にもどります。」（黙って変えない）。
- 傾斜に回転の条件を使わない（今の決まりのまま。別ファイル）。
- 「位置決め精度（ISO230）」のモードは、はじめてモードでは出さない（通常の画面のまま）。

#### 「測る」の流れでの見え方（手順「測り方を確かめる」）

```
  測り方（RWE-200・回転・分割＋再現性）          [登録から自動で入りました]
  分割   10° ごと 36 か所 ／ 細かく 1° ごと 20° ぶん
  再現性 4 か所 × 7 回（0°〜270°）
                                   [このまま進む ▶]   [直す…]
```

登録が無い分は、その場で手順 3〜5 が出る。値は `on_model_entered` が入れたものを読むだけ。

### 2-4. 一旦やめる・戻る（要望 3）

**考え方（案）**: 「一旦やめる」を押した瞬間には、**何も捨てない・機械には何もしない**。画面が1枚出て、そこで人が選ぶ。PC は機械を止められない（運転の開始・停止を PC からしない、は 2026-11-22 の決定）ので、機械を止めるのは人で、画面は絵でそれを案内する。

| いまの様子 | 「一旦やめる」の画面に出すもの | 呼ぶもの |
|---|---|---|
| **機械が動いていない手順**（ほとんど） | つづける／前の手順にもどる／この作業をやめてホームへ／アラームを調べる | `_back`・`_go_home`（今あるもの） |
| **機械に入れる手順の中**（かんたん作成が開いている） | 上と同じ。書いている最中なら「書き終わるまで待つ（おすすめ）」を先頭に。やめるを選ぶと、**今までと同じ確認**が出る | `_close_wizard` → `_close_writer`（今あるもの。新しい止め方は作らない） |
| **測っている途中**（起動ボタンの手順〜測っています） | 一番上に絵で「**① まず機械を止める**（操作盤の送り停止のボタン。あぶないときは非常停止）」。その下に: **つづける**（機械の起動ボタンを押すと続きから。測った値は残っています）／**1か所もどす**／**この測定をやめて、最初から測り直す**（「測った N か所は消えます」と確かめてから）／**やめてホームへ**（同じく確かめてから）／**アラームを調べる** | 1か所もどす＝`MainWindow.undo`、やめる＝`MainWindow.cancel`、測り直す＝今の `_remeasure`（プログラムの呼び出しの手順へ） |
| **測り終えて、まだ保存していない** | 「まだ保存していません」。保存する／保存しないでやめる | `easy_save` |

あわせて直す所:

- 測っている途中の **「もどる」は、上の「一旦やめる」の画面を開く**ようにする（今は取込を続けたまま前の手順へ行ってしまう）。
- 測っている途中に機械が止まったら知らせる: 読む係の値で「非常停止がかかった」「アラームが出た」を見たら、画面の下に赤く「機械が止まっています ▶ どうする？」を出す（押すと上の画面）。**勝手に中止はしない。**「運転中かどうか」の読みは実機未確認なので、これだけでは決めない。

### 2-5. アラーム（要望 4）

```
 ① 機械から読む          ② 意味とやること            ③ 直ったか確かめる
 ┌──────────────┐   ┌──────────────────┐   ┌──────────────────┐
 │ いま出ているもの    │   │ PW0000              │   │ さっき: PW0000        │
 │ ▲ PW0000         │ → │ 機械の画面の文字: …   │ → │ いま:  出ていません ✓  │
 │   電源を切って…    │   │ 意味 / 原因 / やること │   │                     │
 │ ● SW0100         │   │ [電源を入れ直す絵]     │   │ [もとの手順にもどる ▶] │
 │ [もう一度読む]      │   │ [やりました。確かめる▶]│   │                     │
 │ 番号を打って調べる…  │   └──────────────────┘   └──────────────────┘
 └──────────────┘
```

| 手順 | 中身 | 呼ぶもの |
|---|---|---|
| ① 機械から読む | 読む係がもう読んでいる一覧を出す（番号・**機械の画面の文字そのまま**・軸）。1秒ごとに新しくなる。機械が見えないときは「機械につながっていません（電源と LAN ケーブル）」と、今までの「番号を打って調べる」 | `MachinePoller.state()["alarms"]`。かんたん作成が開いている間は読む係が止まっているので、かんたん作成が持っている値を受け取る（`guide_brief()` にアラームの一覧を足す。機械へ2本つながない決まりは守る） |
| ② 意味とやること | アプリの一覧から、**番号がぴったり同じものを先**に出す。数字だけ同じ別の種類は「近い番号（種類が違います）」と分けて出す。**一覧に無いときは「アプリの一覧にありません」と書き、機械の画面の文字を大きく出す**（29件しか無いので、無いほうが多い。無いものを有るように見せない）。やることが絵にできるもの（電源の入れ直し・非常停止をもどす・リセットを押す・原点復帰）は、今ある絵を出す | `fanuc_alarms.search_alarms`（今の検索）。「ぴったりを先」は並べ替えだけ |
| ③ 直ったか確かめる | 「やりました。確かめる ▶」を押すと、読み直して比べる: **消えた ✓／まだ出ている／新しく出たもの**。全部消えたら「直りました」。残っていれば ② にもどる | 比べ方は `focas_ops._alarm_key`（書いたあとに増えたアラームを見るのと同じ） |
| ④ 記録（後の段） | 直ったら1回だけ聞く: 「どれで直りましたか」（②の「やること」＋「ほかのやり方（一言）」）。日時・号機・番号・機械の文字・選んだものを `アラーム記録.csv`（PC 側。マスタの外）に足す。次に同じ番号が出たら「前はこれで直りました」を ② の一番上に出す | `docs/FOCAS_実機確認と要件_20261122.md` §6 ③ の要件そのまま |

- **PC からアラームを消す（リセットする）ことはしない。** 消すのは人が機械で。アプリは読むだけ。
- 書けるようになっている印（SW0100）のように異常でないものは、「これは異常ではありません（設定を書けるようにしている印）」と出す。対応は `focas_ops` の「許しているアラーム」の一覧を使う（新しい一覧は作らない）。

## 7. 設計のあいだに見つけた、今のはじめてモードの直す所（事実。段1・3に入れる）

1. 型式の条件が登録に無いと行き止まり（§1-4）。
2. 測っている途中の「もどる」で、取込が続いたまま前の手順にもどる（§1-6）。
3. 測り終えて保存する前に閉じても、聞かれない（§1-6）。
4. 表示器がつながっているかを見る手順が無い（§1-3）。
5. アラームの番号で、種類の違う説明が1件目に出ることがある（§1-5）。
6. 機械に出ているアラームが2件以上あっても、1件目しか見えない（§1-5）。
