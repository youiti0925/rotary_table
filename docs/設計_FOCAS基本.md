## 0. 結論（先に）

1. **FOCAS は「32bit Python の別プロセス（ヘルパー）」で動かす。** アプリ本体（64bit）とは
   **標準入出力に JSON を1行ずつ**流してやり取りする。ソケットは使わない（ポートを開けない）。
2. **パラメータは1つずつ `cnc_wrparam` で書く。** 書く直前に機械の今の値が「土台」と同じかを読み、
   書いた直後に読み戻す。ファイル丸ごとの流し込みは ① ではやらない。
3. **書く中身は必ず `param_build.prepare()` が決める。** 土台を BASIC から「FOCAS で今取った控え」に
   替えるだけで、作成経路は増やさない。機械へ書くのは「土台と `prepare()` の結果の差」だけ。
   （実機の控え `パラメータ.DAT` に `prepare()` をそのまま当て、3件の変更でちょうど3行だけ変わることを確認済み【事実】）
4. **FOCAS の控えは BASIC フォルダと別の専用フォルダに置く。** BASIC フォルダの中を指定したら断る。
5. **型ごとに「同じ値を書いて戻す」試験が済むまで、その型は書かない。** 実機で書いたことがあるのは
   「バイト型・ラベルなし（0020）」の1種類だけ【事実】。実数・軸型・ビット型はまだ書いていない。
6. **運転開始・プログラム選択・PMC 信号の書込はヘルパーに入れない。** 呼べる DLL 関数を一覧で固定し、試験で見張る。
7. 実機なしで全部の流れを試験できるよう、DLL の代わりになる「偽物の機械」を tests に置く。

## 1. 範囲

### やること（①）

- 読む: 状態・アラーム・識別・パラメータ・プログラム一覧
- 控える: パラメータ・ピッチ誤差補正・マクロ変数・工具補正・全プログラム
- パラメータを書く → 読み戻して照合 → アラーム確認 → PW0000 なら電源入れ直しの案内 → 戻ったら自動で再照合
- 測定プログラムを書く → 読み戻して照合
- 書く前の安全確認・控え・利用者の確認ボタン

### やらないこと（① では作らない）

| しないこと | 理由 |
|---|---|
| 運転開始（サイクルスタート） | 方針4。PC からはしない |
| 運転するプログラムとして選ぶ | 要件メモ §6① にあるが**未試験**。今回の依頼範囲の外。②以降で扱う |
| PWE の ON/OFF | 方針6。人がやる。アプリは SW0100 を見て案内するだけ |
| マクロ変数・ピッチ誤差・工具補正の**書込** | ① では控えるだけ（②の「返事を書く」で扱う） |
| ファイル丸ごとのパラメータ流し込み | §7.3 |
| BASIC 基準での書き直し（方針3） | 差の一覧と番号選びの画面が別に要る。① の書込の仕組みをそのまま使える形にはしておく（§7.9） |
| 0i-D・18i の実装 | 31i だけ。入れ物は用意する（§5） |

## 2. 設計の前に手元のデータで確かめたこと

要件メモに無く、今回、控え（`機械バックアップ_20261122\データ\`）と試験スクリプトを読んで分かったこと。
どれも**読んだだけ**（機械にもリポジトリにも書いていない）。

### 2.1 型コードの残りのビット【事実。意味は一部推測】

`パラメータ一覧.csv`（型コードとラベルの対応 約3万行）を集計した。

| ビット | 分かったこと |
|---|---|
| `0x100` | **付いている番号は全部ラベルが `S`（主軸型）で、`S` の番号は全部これが付いている**（3900個すべて）【事実】。主軸型の印とみてよい |
| `0x20` | 付いているのは 197番号。うち181個は N09802・N09820〜N09999（＝カードのパンチアウトに出ない番号）とぴったり重なる。残り16個は 1860〜1863・3271・9800・9801・9810〜9818【事実】。意味は**未解読** |
| `0x10` | 0001 0002 0010 0020〜0023 0100 0300 … に付く【事実】。「セッティング画面で入れる番号」に見える【推測】 |
| `0x40` | 要件メモのとおり未解読 |
| 系統型（ラベル `L1` `L2`） | **型コードからは見分けられない**（コード0 に「ラベルなし」243個と `L` 612個が混ざる）【事実】。ラベルは控えのファイルから取る |

→ 設計への反映: **型の基本（ビット/バイト/ワード/2ワード/実数）は型コードから、ラベルの種類（なし/L/A/S/T）は控えファイルから**取る。
未解読ビットは「分からない」と画面に出すだけで、禁止の理由にはしない。

### 2.2 FOCAS で取ったパラメータの形【事実】

- 区切り `LF`、先頭 `%\n`、末尾 `%`（最後は改行なし）。6621番号。同じ番号の重複は0。
- 軸は **A1〜A12 の12個**並ぶ（実際に使っているのは A1〜A6）。`fanuc_param.AXIS_LABELS` は A8 までだが、
  値の読み書き（`_SEG`）は A12 でも通った。
- **行の長さが奇数になると末尾に空白が1つ付く**（`N00020Q1P9 ` など）。行の中身の一部として保つ。
- 実数は `P` と `M` の**両方**がある。`N01320Q1A1P-1.0…`、`N01220Q1A1M0.0…`。
  要件メモの「実数は `P-1.0` と書く」は 1320 などの話で、`M` の行も389行ある。使い分けの規則は**未解読**
  （型コードは同じ 4099/4103 に両方が混ざる）。→ `prepare()` は行の文字を保つので影響しない。書込は数値で行うので影響しない。
- 型情報（`cnc_rdparainfo`）は 6653番号、控えは 6621番号。**32個の差の中身は未確認**。

### 2.3 `prepare()` は FOCAS の控えをそのまま土台にできる【事実】

控えの `パラメータ.DAT` を土台に `prepare(raw, {1420: "8000.000", 1815: "001*0000", 1821: "360000"}, axis=4, …)` を回した。

- プレビュー行 3件（20000.0→8000.0 / 00000000→00100000 / 6000→360000）、点検の指摘 0件
- `newtext` と土台を行ごとに比べると、**変わったのはその3行だけ**。行数も同じ（6623行）
- `param_origin.classify` は「PC製（区切りが LF のみ）」と判定する（要件メモのとおり）

### 2.4 プログラムの読み戻しに付く空白【事実と未確認】

試験で書いた O0901 は、もともと機械が出したファイルで、**最初から行末に詰め物の空白が入っていた**
（`G04X0. ` など）。読み戻しが「1バイト一致」だったのはそのため。
**アプリが作ったプログラム（詰め物なし）を書いたとき、機械が空白を足して返すかは未確認。** → §8.4

## 4. ヘルパー方式

### 4.1 なぜ別プロセスか【事実】

- `Fwlib32.dll` は 32bit 版しか無い。64bit のプロセスには読み込めない。
- アプリ本体は 64bit Python + PySide6。PySide6 は 32bit Windows 用が無いので、本体を 32bit にはできない。
- 32bit Python から ctypes で DLL を呼ぶ形は、この PC で動いた。Cylance は PowerShell を止めたが、これは止めなかった。

### 4.2 通信は標準入出力にする（ソケットにしない）

| 比べた点 | 標準入出力 | ローカルソケット |
|---|---|---|
| ポートを開けるか | **開けない** | 開ける（127.0.0.1 でも Windows ファイアウォールや Cylance が反応しうる【推測】） |
| 本体が落ちたとき | 入力が閉じるのでヘルパーも**自分で終わる** | 残りうる（機械との接続を握ったまま） |
| ポートの取り合い | 無い | FTP サーバー(21)・Web モニタと並んで管理が増える |
| 試験 | `subprocess` だけで書ける | 空きポート探しが要る |
| 弱点 | DLL が標準出力に何か書くと壊れる | — |

弱点への手当て: ヘルパーは起動直後に**本物の標準出力を自分だけで握り**、`sys.stdout` は標準エラーへ向け直す。
標準エラーはアプリが `focas_helper.log` に流す（診断用）。

### 4.3 起動

```
<32bit python.exe> -I -u <focas_helper.py> --dll-dir <DLLのフォルダ>
```

- `-I`（孤立モード）: 環境変数や利用者の site-packages に左右されない。ヘルパーは標準ライブラリだけで動く。
- `-u`: 出力をためない。
- 黒い窓を出さない（`CREATE_NO_WINDOW`）。
- 32bit Python の場所は設定 `focas_python32`
  （既定 `C:\Users\AA4344\AppData\Local\Python\pythoncore-3.14-32\python.exe`。PC ごとに違うので画面から選べる）。
- DLL は**フルパスで** `ctypes.WinDLL` する（試験スクリプトと同じ【事実】）。探す順: 設定 `focas_dll_dir` →
  `C:\Program Files (x86)\FANUC SERVO GUIDE\` → `C:\Windows\SysWOW64\`。
- 関数は全部 `restype = c_short` を付ける（付けないと成功 0 が大きな数に見える【事実】）。

起動するとヘルパーは最初に1行だけ出す。

```json
{"hello": 1, "proto": 1, "bits": 32, "python": "3.14.10", "dll": "C:\\...\\Fwlib32.dll", "dll_ok": true}
```

アプリは `bits == 32`・`proto` の一致・`dll_ok` を見る。合わなければつながずに、理由を平易に出す（§4.6）。

### 4.4 命令の形

1行に1つ。文字は ASCII だけ（`ensure_ascii=True`）。日本語のアラーム文言は `\uXXXX` で運ばれるので、
コードページの違いで化けない。プログラムや控えの**中身は base64**（1バイトも変えないため）と SHA-256 を付ける。

```
→ {"id": 7, "cmd": "param_read", "args": {"no": 1420, "label": "A4"}}
← {"id": 7, "ok": true, "result": {"no": 1420, "label": "A4", "kind": "real", "value": "20000.0", "raw": "..."}}

← {"id": 8, "ok": false, "error": {"kind": "focas", "func": "cnc_wrparam", "rc": 7, "name": "EW_PROT"}}
← {"id": 9, "event": "progress", "done": 12, "total": 62, "note": "O2100"}      （長い命令の途中経過）
```

- 命令は**1つずつ**。前の返事が来るまで次を送らない（アプリ側でロックする）。
- ヘルパーは1本のスレッドで動く。機械との接続（ハンドル）は取ったスレッドで使う【仕様】ので、これで安全側。
- ヘルパーは画面を開いている間ずっと動かす（状態を1〜2秒ごとに読むため。毎回起動し直さない）。

### 4.5 時間切れ

| 命令 | 待つ時間（設定で変えられる） | 根拠 |
|---|---|---|
| 起動〜hello | 10秒 | — |
| `connect` | 15秒 | `cnc_allclibhndl3` の時間切れを10秒で呼んでいる【事実】＋余裕 |
| 状態・アラーム・1件の読み書き | 5秒 | — |
| 控え（パラメータ全部） | 180秒 | 試験スクリプトは120秒で打ち切る作りで、取れた【事実】 |
| プログラム1本 | 60秒 | — |
| 型情報の全読み | 60秒 | — |

時間切れのとき:

1. ヘルパーを**止める（kill）**。DLL の中で固まっていると `quit` も届かないため。
2. 画面は「切れました」にする。
3. **書込の命令が時間切れになったら、書けたかどうかは「不明」と表示する。** 自動でやり直さない。
   つなぎ直して**読み戻した値で**判定する（旧値のまま＝書けていない／新値＝書けている／どちらでもない＝止めて人に見せる）。

`EW_BUFFER`（戻り値10）は「少し待って同じ分を送り直す」合図【事実】。20ミリ秒待って繰り返すが、
全体の時間切れ（上の表）で必ず抜ける。試験スクリプトの書込側には上限が無かったので、そこは直す。

### 4.6 エラーの伝え方

`error.kind` を次の種類に分け、`focas_client` が**平易な日本語と「次に見るところ」**に直す。
生の戻り値と関数名は必ず一緒に出す（黙って丸めない）。

| kind | 例 | 画面に出す文（案） |
|---|---|---|
| `no_python` | 32bit Python が見つからない | 「FOCAS 用の Python（32bit）が見つかりません。設定で場所を選んでください」 |
| `not_32bit` | 64bit の Python を指定した | 「これは 64bit の Python です。FANUC のライブラリは 32bit でしか動きません」 |
| `no_dll` | Fwlib32.dll が無い・読めない | 「FANUC のライブラリが見つかりません。SERVO GUIDE が入っているか確認してください」 |
| `connect` | `cnc_allclibhndl3` が 0 以外 | 「機械につながりません（戻り値 -16）。LAN ケーブル・IP アドレス・機械の電源を確認してください」 |
| `focas` | 個々の関数が 0 以外 | 関数名・戻り値・意味（下の表） |
| `lost` | 途中で切れた（-8 / -16） | 「機械との接続が切れました」 |
| `timeout` | 返事が来ない | 「機械から返事がありません。○秒待って打ち切りました」 |
| `refused` | ヘルパー自身が断った | 「同じ名前のプログラムが既にあります」など |
| `unsupported` | まだ作っていない機種 | 「この機種（0i-D）はまだ対応していません」 |
| `protocol` | 返事が JSON でない | 「内部エラー」＋ `focas_helper.log` の場所 |

戻り値の意味【仕様。実機で見たのは 0・6・10 だけ】

| 値 | 名前 | 意味 | この設計での扱い |
|---|---|---|---|
| 0 | EW_OK | 正常 | — |
| 3 | EW_NUMBER | 番号が無い | その番号は機械に無い |
| 4 | EW_ATTRIB | 軸・種別の指定違い | 型の表が違う。止める |
| 5 | EW_DATA | 値が範囲外など | 止める |
| 6 | EW_NOOPT | オプションなし | 控えで「読めず」と記録（ワーク原点オフセットで出た【事実】） |
| 7 | EW_PROT | 書込禁止 | PWE が OFF かもしれない【推測】。案内を出す |
| 10 | EW_BUFFER | 待って再送 | 20ms 待って繰り返す【事実】 |
| 12 | EW_MODE | モード違い | モードを変える案内 |
| 13 | EW_REJECT | 受け付けない（運転中など） | 止める |
| 15 | EW_ALARM | アラーム中 | 止める |
| -1 | EW_BUSY | 処理中 | 少し待って1回だけ読み直す（書込はやり直さない） |
| -8 / -16 | EW_HANDLE / EW_SOCKET | 接続なし | `lost` |

### 4.7 終わり方

- 画面を閉じる → `quit` を送る → ヘルパーが `cnc_freelibhndl` して終わる → 3秒待って終わらなければ止める。
- アプリが落ちた → 標準入力が閉じる → ヘルパーは `cnc_freelibhndl` して終わる。
- 書込の途中で閉じようとしたら「いま書いている1件が終わってから止めます」と出し、**1件の途中では切らない**。

### 4.8 exe にしたとき【未決】

今の配布は PyInstaller の1ファイル exe。ヘルパーは外の 32bit Python に渡す `.py` なので、exe の外に実体が要る。

- 案A: `focas_helper.py` を **exe の隣に置いて配る**（`settings.app_dir()` と同じ場所）。分かりやすい。
- 案B: exe の中に入れておき、実行のたびに一時フォルダへ展開されたものを使う。
  一時フォルダのスクリプトを Cylance が止めるかは**未確認**。

**案A を勧める。** 探す順: 設定 `focas_helper_path` → exe の隣 → パッケージのフォルダ（開発時）。
起動時に、隣のヘルパーの `proto` がアプリの期待と違えば「ヘルパーが古い」と出す。

## 5. 機種の違いを足せる形

ヘルパーの中を2層にする。

```
命令（機種に依らない名前）   prog_list / prog_read / prog_write / prog_delete / param_dump / …
        │
機種ごとの手順（Family）    Family31i（実装する）  Family0iD / Family18i（名前だけ。呼ぶと unsupported）
        │
DLL 関数                    cnc_rdpdf_alldir / cnc_upstart4 / …      cnc_rdprogdir / cnc_upstart3 / …
```

- どの Family を使うかは `cnc_sysinfo` の `cnc_type` で決める（`31` → `Family31i`）。
  35i は 31i と同じ手順で動くと要件メモにあるが**実機未確認**なので、最初は `unsupported` にしておき、
  読むだけの確認が済んだら `Family31i` に割り当てる（設定の一覧で切り替え）。
- プログラムの指し方を機種に依らない形にする: `{"folder": "//CNC_MEM/USER/PATH1/", "name": "O901", "number": 901}`。
  31i は `folder + name`、番号で扱う機種は `number` だけを使う。`focas_ops` と画面は `folder` が無い機種でも動くよう、
  「フォルダの木」が空でも一覧が出る作りにする。
- パラメータの型コードの読み方も Family が持つ（0i-D・18i の型コードは**未確認**。18i には実数型が無いはず【仕様】）。
- 「書ける型の確認済み表」（§7.4）は機種ごとに持つ。
- **機種を足すときの手順**（要件メモ §6①「機種ごとに同じ値を書いて戻す試験を1回ずつ」）:
  ① 読むだけの自己診断（§12-A）→ ② 型ごとの同値書込（§12-B）→ ③ その機種を有効にする。

### 6.2 状態の読み方

`cnc_statinfo` の数値の意味【仕様。実機で見たのは「MDI・リセット・アラーム1」の1通りだけ。数値そのものは記録に残っていない】

| 項目 | 値 |
|---|---|
| aut（モード） | 0 MDI / 1 メモリ / 3 編集 / 4 ハンドル / 5 ジョグ / 9 原点復帰 / 10 リモート ほか |
| run（運転） | 0 リセット（止まっている）/ 1 停止 / 2 一時停止 / 3 運転中 / 4 MSTR |
| motion | 0 なし / 1 移動中 / 2 ドウェル |
| emergency | 0 なし / 1 非常停止 / 2 リセット中 |
| alarm | 0 なし / 1 アラーム / 2 電池低下 ほか |

→ **運転中・一時停止・非常停止のときの実際の数値を、実機で1回ずつ読んで確かめる**（§12-A。読むだけ）。
確かめるまで、画面には日本語の読みと**生の数値を並べて**出す。

アラームの種類の番号【仕様。実機で見たのは 種類0・番号100＝SW0100 だけ】: 0 SW / 1 PW / 2 IO / 3 PS / 4 OT / 5 OH / 6 SV / 7 SR / 8 MC / 9 SP / 10 DS ほか。
→ **PW0000 が「種類1・番号0」で来るかは未確認。** §7.7 と §12-C。

アラームは `fanuc_alarms.search_alarms()` で内蔵表を引き、原因と対処の目安を横に出す（番号は `SW0100` の形に組み立てる）。

### 6.3 控え（バックアップ）

**置き場所**: 設定 `focas_backup_dir`（既定 `機械バックアップ`。相対ならアプリのフォルダ基準。`save_root` と同じ決まり）。

```
<focas_backup_dir>/
  <CNC ID の先頭8桁>_<機種>[_号機NN]/            例 3C7B5D01_31i_号機23
    20261122_160451_書込前/
      パラメータ.DAT            機械が返したバイトそのまま（区切り LF）
      ピッチ誤差補正.DAT
      カスタムマクロ変数.DAT
      工具補正.DAT
      型情報.csv                cnc_rdparainfo（番号, 型コード）
      プログラム/CNC_MEM/USER/PATH1/O901 …   フォルダの木のまま
      控え_情報.json            日時・接続先・機種・版・CNC ID・登録本数と残り・各ファイルの大きさと SHA-256・
                                読めなかったもの（例: ワーク原点オフセット 戻り値6）・"source": "focas"
      控え表.txt                人が読む一覧
```

決まり:

1. **BASIC フォルダ（設定 `param_basic_dir`）と同じ場所・その中は断る。** 設定を保存するときと、控えを書く直前の2回見る。
   製品データのフォルダ（`param_product_dir`）も同じく断る。
2. ファイル名を `F<数字>BASIC…` にしない（`controllers.basic_file_for_unit` が拾わないように）。
3. **受け取ったバイトを変えない。** 改行を `LF CR CR` に直して保存しない（直すと「実機が出したもの」と見分けが付かなくなり、
   BASIC に紛れたとき気づけない）。
4. 出どころは**中身の形ではなく `控え_情報.json` で持つ**。`param_origin.classify` は「PC製」と言うが、
   FOCAS の控えについてはその判定を使わない（§7.1）。
5. **取った直後に点検する**（調査記録 §17「バックアップは取った直後に見ないと壊れていても気づけない」）:
   末尾が `%` か／`fanuc_param.validate_prm` の指摘／番号の数／プログラムは `控え表` の本数と一覧の本数が合うか。
   指摘があれば控えを「不完全」として、書込に進ませない。
6. 号機番号は機械から読めない【事実】。`cnc_type`・版・軸数で号機マスタを引いて候補を出し、
   **人が選ぶ**（候補が1つでも「号機23 とみられます」と出すだけ。黙って決めない）。フォルダ名は CNC ID が主。

控えるもの: 既定は「パラメータ類4つ＋型情報＋全プログラム」。書込の直前の控えは時間を短くするため
「パラメータ類＋書き替えるプログラムだけ」を選べる（その日最初の1回は全部取る）。

## 7. パラメータを書く

### 7.1 土台は「いま取った控え」。作るのは `prepare()`

```
① つなぐ → ② 控えを取る（必ず。この回の控え） → ③ 控えの パラメータ.DAT を土台 raw にする
④ plan = param_build.prepare(raw, 製品値…, reference="")     ← 今ある作成画面の _plan() をそのまま通す
⑤ 書くもの = fanuc_param.diff(raw, plan["newtext"])          ← [(番号, ラベル, 今の値, 書く値)]
⑥ プレビュー（plan["rows"]）→ 確認 → 安全確認 → 1件ずつ書く
```

- **`prepare()` を通さない経路は作らない。** FOCAS だからといって値の解決（`'` の除去・`*` の合成・`+108.000`→`108.0`）・
  0にする・ソフトリミットの扱い・点検を別に書かない。土台の `raw` が替わるだけ。
- **機械に書くのは `raw` と `newtext` の差だけ**（⑤）。プレビューの「変わる行」の数と ⑤ の件数が合わなければ、
  書かずに止めて両方を見せる（画面と中身のずれを書込の前で捕まえる。試験でも固定する）。
- `reference=""` にする理由: 土台が機械そのものなので、番号の照合相手は要らない。
  今の `gui.reference_backup()` は「土台が実機の形か」を `classify` で見るので、FOCAS の控え（PC製と判定される）を渡すと
  BASIC の和集合と比べてしまい、**機械に実在する N09802・N09820〜N09999 を「実機に無い番号」と警告してしまう**。
  → 作成画面の `_plan()` に「土台は FOCAS の控え」という印を渡し、そのときは `reference=""` にする（判定の形を変えるのではなく、
  出どころを呼ぶ側が知っているのでそれを渡す）。
- 区分が「BASICに無い」の行（＝**機械にその番号が無い**）は書けない。赤で出し、書込の一覧から外したことを件数で出す。
  FOCAS が土台のときは見出しの文言を「機械に無い」に替える。
- 土台がヘッダ＋CSV 形式になることは無い（FOCAS の控えは必ず N 形式）。`plan["fmt"] != "fanuc"` なら書かない。
- `plan["newtext"]` は「書いたあとの機械の姿」でもある。控えのフォルダに `書込後の予定.DAT` として残す（区切りは LF のまま）。

### 7.2 「0にする」をどうするか【未決】

カードの流れでは 1850・1851・1852 を**全軸**0にしている（BASIC は別の機械の実測値を持ちうるため）。
FOCAS では土台が「今の機械」なので、同じことをすると**試験装置のほかの軸の実測値まで0にする**。
号機23 の控えではこの3つは全部0だったので今は差が出ないが、ほかの機械では出うる。

- 案1: FOCAS が土台のときは「0にする」の既定を**製品の軸だけ**にする
- 案2: 既定は「しない」にして、プレビューで選ばせる
- 案3: カードと同じ（全軸）

どれでも `prepare()` の引数（`zero_params`）で表せるが、「製品の軸だけ0」は今の `prepare()` に無い。
足すなら `prepare()` の中に足す（外で別にやらない）。**利用者に決めてもらう。**

### 7.3 1つずつ書く（ファイル丸ごとにしない）

| | 1つずつ `cnc_wrparam` | ファイル丸ごと（`cnc_dwnstart4` 種別2） |
|---|---|---|
| 実機で動いたか | **動いた**（0020）【事実】 | 試していない |
| 書く範囲 | 変える所だけ（数件〜数十件） | 2万4千か所全部（積算カウンタ・サーボ調整値も上書き） |
| 方針2「製品の値だけ変える」 | 合う | 合わない |
| 途中で止まったとき | どこまで書いたか1件単位で分かる | どこまで入ったか分からない |
| 1件ごとの照合 | できる | できない |
| 速さ | 数十件なら数秒【推測】 | — |

→ **1つずつ。** 1件 ＝ 1番号 × 1ラベル（軸型なら1軸ぶん）。

### 7.4 型の決め方と「確認済みの型」

1件ごとに次の2つで型を決める。

- **基本の型** ＝ 型コード（`型情報.csv`）: 下位2ビット 0 ビット / 1 バイト / 2 ワード / 3 2ワード、`0x1000` が立てば実数
- **ラベルの種類** ＝ 控えファイルのラベル: なし / `L`（系統）/ `A`（軸）/ `S`（主軸）/ `T`

実機で書いたことがあるのは **「バイト × ラベルなし」だけ**（0020）【事実】。そこで:

- 機種ごとに「確認済みの型」の表を持つ（設定 `focas_verified_kinds`。例 `{"31i": ["byte/none"]}`）。
- 書込の一覧に**確認済みでない型**が混ざっていたら、その行に印を付け、
  「この型は、この機種ではまだ書いたことがありません。先に『同じ値を書く確認』をします」と出す。
- **同じ値を書く確認** ＝ その型の番号を1つ選び、**今と同じ値**を書いて、読み戻して、アラームが増えないことを見る。
  通ったら表に足す（日時・番号・CNC ID を記録に残す）。これも書込なので、**利用者の確認ボタンを通す**。
- 確認に使う番号は、書込の一覧の中のその型の1件目を候補に出す（これから書く番号そのもので確かめるのが一番確か）。

これは「推測で禁止」ではなく、要件メモ §6①の「同じ値を書いて戻す試験を1回ずつ」を型ごとに行う仕組み。
未解読ビット（`0x10` `0x20` `0x40`）が付いている番号は、**付いていること**を行に出すだけで、扱いは変えない。

### 7.5 `cnc_wrparam` に渡す形

先頭4バイトは `<hh`（番号, 軸）。長さ ＝ 4 ＋ データの大きさ。

| 基本の型 | データ | 例 | 確かめたか |
|---|---|---|---|
| バイト | 1B | `<hhB`(20, 0, 4) 長さ5 | 【事実】0020 で動いた |
| ビット | 1B（8ビットまとめて） | `00100000` → 0x20 | 【仕様】未確認 |
| ワード | 2B 符号つき | `<hhh` | 【仕様】未確認 |
| 2ワード | 4B 符号つき | `<hhi` | 【仕様】未確認 |
| 実数 | 8B（値の整数, 小数点以下の桁数） | `<hhii` | 【仕様】未確認 |

軸の欄:

| ラベル | 渡す値 | 確かめたか |
|---|---|---|
| なし | 0 | 【事実】 |
| `A4` | 4（軸の番号） | 【仕様】未確認。**読むだけで確かめられる**（1020 を軸1〜6で読んで 88 89 90 65 66 67 になるか） |
| `S1` | 1（主軸の番号） | 【仕様】未確認。読むだけで確かめられる |
| `L1` `L2` `T1` | **分からない** | 系統の切り替え（`cnc_setpath`）が要るのか、軸の欄で渡すのか未確認。**読んで確かめるまで書かない** |

- **ビット型は1バイトまとめて書く。** `prepare()` が `*` を土台のビットで埋めた8桁を出すので、それをそのまま1バイトにする。
  書く直前に機械の今の8ビットが土台と同じことを確かめる（§7.6）ので、ほかのビットを壊さない。
- バイト型の符号（128 以上をどう読むか）は、全部読んで控えと比べれば決まる（§12-A）。それまでは範囲外の値を書かない。

**実数の書き方**:

1. 書く前にその番号を `cnc_rdparam` で読む → 機械が返す「小数点以下の桁数」を得る。
2. 書く値の文字（例 `8000.0`）を10進のまま扱い（浮動小数点を使わない）、`整数 = 値 × 10^桁数` にする。
3. **割り切れなければ書かない**（例: 桁数3の所に `0.0005`）。丸めて書かない。理由を出して止める。
4. 同じ桁数で書く。読み戻しは**数値として**比べる（`20000.0` と `20000` は同じ）。

「値 × 桁数」の2つ組で読み書きする形そのものが【仕様】で未確認。§12-A（読むだけ）で形を、§12-B（同値書込）で書込を確かめる。
旧書式の8台で起きた「1000倍ずれる」事故（調査記録 §14）と同じ種類の危険なので、**形を確かめるまで実数は書かない**。

### 7.6 1件の流れ（比べてから書く）

```
1. 読む   今の機械の値 == 土台の値 か      違えば → 止める「控えを取ったあとで機械の値が変わっています」
2. 書く   cnc_wrparam                      戻り値が 0 以外 → 止める
3. 読む   今の機械の値 == 書いた値 か      違えば → 止める
4. アラームを読む                          許した以外のアラームが増えた → 止める
```

- **1件でも止まったら、残りは書かない。** どこまで書いたかを一覧で見せる。
- 止まったあとは「書いた分を元に戻す」ボタンを出す（旧値を同じ流れで書き戻す。これも確認ボタンを通す）。自動では戻さない。
- 「中止」ボタンは**次の1件の前**で止まる。
- 値の比べ方: 整数・ビットは文字を数にして比べる。実数は10進の数として比べる。
- 全部書き終わったら、**パラメータをもう一度丸ごと吸い出して `newtext` と全行比べる**。
  書いた所が合っていることに加え、**書いていないのに変わった番号**を一覧で出す
  （6753・6754 の積算カウンタのように動いて当然のものもあるが、隠さず出す。黙って除外しない）。

### 7.7 書く前の安全確認（「書ける状態」）

確認ボタンを押した瞬間と、**1件ごとの直前**に見る。

| 見るもの | 書ける条件 | 根拠 |
|---|---|---|
| つながっている | CNC ID が控えを取ったときと同じ | 途中で別の機械に替わっていないこと |
| 運転 | `run == 0`（リセット）かつ `motion == 0` | 方針5 |
| 非常停止 | `emergency == 0` | 方針5 |
| アラーム | **無い、または SW0100 だけ**（書込の途中は PW0000 も許す） | 下 |
| 控え | この回に取った控えが「完全」 | 方針1 |
| 型 | 一覧の全行が確認済みの型 | §7.4 |
| PWE | SW0100 が出ている | 試験スクリプトがこの条件で書いた【事実】 |

**「アラーム中は書かない」と PWE の関係**: パラメータを書くには PWE を ON にする。ON にすると SW0100 が出て、
`statinfo` の alarm は 1 になる【事実】。だから「アラームが1つでもあれば書かない」にすると**永久に書けない**。
→ 「SW0100 だけなら書ける。ほかのアラームが1つでもあれば書かない」とする。許すアラームの一覧は設定に持ち、画面に出す。

- SW0100 が**出ていない**とき: 「機械のセッティング画面で『パラメータ書込』を 1 にしてください」と案内して待つ（アプリは PWE を触らない）。
- モード（MDI・編集など）では**止めない**。書込時のモードは記録に残っておらず、どのモードで書けるかは確かめていない。
  推測で禁止せず、戻り値（12＝モード違い）が出たらそのとき案内する。
- 書き終わったら「PWE を 0 に戻してください」と出す。

### 7.8 PW0000（電源の入れ直し）と自動の再照合

書込の最後のアラーム確認で PW0000 があれば:

```
[書込完了・電源待ち] ──つながらなくなった──▶ [電源が切れた] ──つながった・CNC ID が同じ──▶ [戻ってきた]
        │                                                                                    │
        └─ 画面:「電源を入れ直してください。入れ直したら自動で確かめます」                   ▼
                                                                          [再照合] → [完了] 結果とアラームを表示
```

- 待っている間、5秒ごとに短い時間切れ（3秒）で `connect` を試す。時間の上限は付けない（昼休みをまたいでもよい）。
- 「戻ってきた」あと、状態が読めるようになってから再照合する。再照合 ＝ 書いた全件の読み戻し ＋ パラメータ丸ごとの吸い出しと `newtext` の比較。
- **CNC ID が違えば再照合しない**（別の機械につながった）。
- 再照合のあとのアラームは全部出す。原点復帰の要求など、**電源を入れ直したから出るもの**があるので、
  アプリは「書込は合っています／アラームが○件あります」と分けて言う。アラームを書込の失敗とは言わない。
- 書込の内容と進み具合は**ファイルに残す**（控えのフォルダの `書込ジョブ.json`: CNC ID・各件の旧値/新値/結果・状態）。
  アプリや PC を止めても、次に同じ CNC ID につないだとき「前回の再照合が残っています」と出して続きができる。
- 電源を切らないまま待っているとき（つながったまま PW0000 が出続ける）は「まだ電源が切られていません」と出す。

**PW0000 の見分け方は未確認**（種類1・番号0 で来るはず【仕様】）。確かめるまでは、書込のあとに
「書く前に無かったアラーム」を全部、番号・種類の生の値・文言つきで出し、
文言が内蔵表の PW0000（`fanuc_alarms` の「電源を切ってください」）に当たるものを電源待ちの合図にする。
見分けられなかったときのために、手で「電源を入れ直すので待つ」に入るボタンも置く。

### 7.9 あとで足すもの（方針3: BASIC 基準で書き直す）

① の書込は「(番号, ラベル, 今の値, 書く値) の一覧」を受け取る形にしておく。
方針3 は「今の機械と BASIC の差の一覧から、人が選んだ行」を同じ形で渡せばよい。画面は別に作る（①の範囲外）。

## 8. 測定プログラムを書く

### 8.1 流れ

```
プログラム作成画面のプレビューの文字（今 ncsend.send に渡しているものと同じ）
  → fanuc.nc_bytes(text, EOB_LF)        ← 整形は今の関数をそのまま通す（; を落とす・コメント整形）
  → O番号ごとに分ける（本体と再現サブ）
  → 1本ずつ: 先頭 "\n" ＋ 本文 ＋ 末尾 "%" の形にして cnc_dwnstart4 / cnc_download4 / cnc_dwnend4
  → 1本ずつ読み戻して比べる
```

- `fanuc.nc_bytes()` を必ず通す約束（CLAUDE.md）を守る。区切りだけ `LF` を指定する
  （機械の中は `LF` で持つ。FOCAS には `LF` 区切り・先頭 `\n`・末尾 `%` で渡して入った【事実】）。
- **O番号ごとに分けて1本ずつ送る。** 実機で通したのは「1回の送信に1本」だけ。
  本体とサブを1回で流して両方登録されるかは未確認なので、確かめた形だけを使う。分けるのは送り方だけで、各ブロックの中身は変えない。
- 送り先フォルダは設定 `focas_prog_folder`（既定 `//CNC_MEM/USER/PATH1/`）。画面でフォルダの木から選べる。
- 機械の一覧に出る名前は `O901`（先頭の0なし）【事実】。同名の判定は数字で比べる。

### 8.2 書く前の確認

| 見るもの | 条件 | 根拠 |
|---|---|---|
| 書ける状態 | §7.7 と同じ（リセット・非常停止なし・アラームは無いか SW0100 だけ）。PWE は要らない【推測。O901 を書いたとき PWE が ON だったかは記録に無い】 | 方針5 |
| 登録できる残り本数 | 送る本数以上 | **空きがあっても枠が0だと入らない**【事実】 |
| 空きメモリ | 送る大きさ以上 | — |
| 同じ番号 | 無い。あれば §8.3 | 試験スクリプトは「あれば書かない」だった |
| O8000〜O9999 | 3202 の NE8・NE9 を読み、保護が効いていそうなら**知らせる**（止めない） | 調査記録 §2 |
| 書く中身 | `fanuc.validate()` の指摘が無い | 今の保存と同じ点検 |

### 8.3 同じ番号が既にあるとき

黙って上書きしない。黙って別の番号にもしない。

1. 機械の中のそのプログラムを読んで**控えに保存**する。
2. 中身が同じなら「同じものが入っています。書きません」で終わり。
3. 違えば、違いを見せて「入れ替える」を選ばせる。入れ替え ＝ 控えを確かめる → `cnc_pdf_del` → 書く → 読み戻す。
   消すのは**その1本だけ**（パスは `フォルダ + 名前` で、名前に `/` が入っていたら断る）。
4. 消したあと書込に失敗したら、控えから**元のものを書き戻すか**を聞く。

### 8.4 読み戻しの比べ方

- まず**1バイトずつ**比べる（読み戻し ＝ `%` ＋ 送ったもの、が実機で成り立った【事実】）。
- 合わなければ、**各ブロックの末尾の空白を除いて**比べる（§2.4。機械が詰め物を足すかもしれない）。
- 画面には「完全に一致」「空白の詰め物を除いて一致（○か所）」「**違う**（最初の違いは○行目）」のどれかを出す。
  2番目を黙って「一致」と言わない。
- 違ったら、機械に入ったものを消すかどうかを聞く（自動では消さない）。

書き終わったら「機械でこのプログラムを選んで、スタートは機械で押してください」と出す（今の送信と同じ文面）。

## 15. この設計で分からなかったこと（まとめ）

- アプリが作ったプログラムを書いたときの読み戻しの形（空白）。本体とサブを1回で送れるか。
- プログラムを書いたときに PWE が ON だったか、どのモードだったか（記録に無い）。どのモードで書けるか。
- exe から起動したときの Cylance の反応。
- 0i-D・18i・35i は何も確かめていない。

## 16. 実装で変えた点（実装時に書き足す）

設計から変えた所と、その理由。段ごとに足す。

### 段1（focas_helper ＋ FakeFwlib）

- **呼べる DLL 関数の一覧（`ALLOWED_FUNCS`）は、段1〜3では「読む関数」だけ**にした（§6.1 の表のうち
  `cnc_wrparam`・`cnc_dwnstart4`/`cnc_download4`/`cnc_dwnend4`・`cnc_pdf_del` は入れていない）。
  段4以降で足す。試験は「書込・削除・運転開始・PMC・サーチ系が一覧に無いこと」と
  「ヘルパーのコードに一覧外の DLL 名が出てこないこと」を見張る。偽物の機械には書込系の関数も置いてあり、
  ヘルパーが誤って呼べば試験が落ちる。
- 命令を足した: `connect`・`disconnect`・`param_read_many`（まとめ読み。自己診断用）・`prog_list` の
  `recursive`（フォルダの木ごと）。`quit` は設計どおり。書込・削除の命令名は無い（`bad_args` になる）。
- エラーの種類を足した: `not_connected`（つながっていない）・`bad_args`（命令の引数が変）・
  `internal`（ヘルパー内の想定外の例外。返事は必ず JSON 1行）。設計 §4.6 の表への追加。
- `cnc_rdparainfo` の個数は、実機で動いた `param_csv.py` / `ptype_probe.py` と同じく
  **値渡し（`c_ushort`）**で呼ぶ。戻りの件数が確実に取れないので、番号が増えない所
  （0 で埋まった余り）で打ち切り、同じ番号は1回だけ数える。`next_no` が進まなければ止まる。
- アラームは一度に 10 件まで読み、10 件に届いたら `truncated: true` を返す（実機の読み方に合わせた）。
- DLL が読めなかったとき、ヘルパーは hello に `dll_ok: false` と `dll_error` を付けて**自分で終わる**（終了コード 3）。
- `Helper(lib, sleep=…, clock=…, families=…)`・`serve(lib, stdin, stdout, hello=…)` の引数は、
  本番も試験も同じ形で使う（時間待ちを試験で止めるため）。偽物を読み込む引数は無い。
- 偽物の機械の仮定（実機で未確認）: 系統型 `L1`・`L2` は軸の欄 0/1 → L1、2 → L2 で読める。
  実機でどう指すかは §12-A2 で確かめる。ヘルパーは `L`・`T` ラベルを**軸の指定なしでは読まない**（`refused`）。

### 段2（focas_client）

- エラーの種類を足した: `no_helper`（focas_helper.py が見つからない）・`helper_old`（hello の proto が合わない）。
  `describe()` が種類ごとの日本語と「次に見るところ」を返す。`focas`・`connect`・`lost` の文には関数名と戻り値を必ず入れる。
- 返事が JSON でない・空行・途中で切れた行のときは、`protocol` を出して**ヘルパーを止める**
  （読み取りの同期が取れなくなるため）。次の命令で起動し直す。設計 §4.5 の「時間切れで止める」と同じ扱い。
- 別の id の返事（古い返事）は捨てて待ち続ける。時間切れは全体の時間で数える。
- 32bit かどうかの確認は `FocasClient(expect_bits=32)` が既定。ヘルパー起動の試験だけ、手元の 64bit Python で回すために
  偽物のヘルパーが `bits: 32` と名乗る（確認自体は本番と同じ。`expect_bits=None` で緩められるのは呼ぶ側の引数）。
  試験の入口は `tests/fake_focas_helper.py`。振る舞いは環境変数 `FAKE_FOCAS_SCENARIO`（JSON）で決める。
- `FocasClient(env=…, extra_args=…)` は子プロセスの環境と追加の引数。本番は使わない（試験が偽物の振る舞いを渡すのに使う）。
- 32bit Python の既定の場所は、利用者名を書かずに `LOCALAPPDATA\Python\pythoncore-*-32\python.exe` などを探す
  （`resolve_python32`）。設定 `focas_python32` があればそれを使う。
- `FocasClient.decode_data()` は prog_read・param_dump の中身を取り出すとき、サイズと SHA-256 を確かめる
  （壊れていたら `protocol`）。

### 段3（控え ＋ FocasDialog）

- **控えの処理は `focas_ops.py` ではなく `nd287_app/focas_backup.py` に分けた**（設計 §3 は focas_ops に入れる形）。
  理由: 控えは Qt も業務の流れも要らない単独の部品で、BASIC フォルダの保護・号機候補・点検・最新の控え探しが
  まとまっている。`focas_ops.py` には「書ける状態の判定」（§7.7）・自己診断（§12-A）・「いまどこで止まっている？」だけを置いた。
  書込の流れ（段4以降）は `focas_ops.py` に足す。
- 控えの置き場所の確認は**3か所**: 画面で設定を保存するとき（`FocasDialog._persist`）・`take_backup` の最初（置き場所）・
  フォルダを作る直前（最終のフォルダ）。置き場所が不適切なとき、画面は**前の置き場所で黙って取らずに**止める。
  機械には、置き場所の確認が済むまで1度も命令を送らない（試験で固定）。
- 控えるもの: パラメータ・ピッチ誤差補正・カスタムマクロ変数・工具補正（必須）と、ワーク原点オフセット（任意。
  戻り値 6 で読めなかった【事実】ので、読めなくても控え全体は「完全」のまま。`控え_情報.json` の `unread` に残す）、
  型情報（`型情報.csv`）、全プログラム（`プログラム/CNC_MEM/USER/PATH1/O901` のように木のまま）。
  §13 の決定どおり「全部」を取る（短い方の選択肢は作っていない）。
- 「不完全」にする条件: 必須の種別が読めない／末尾が `%` でない／`fanuc_param.validate_prm` の指摘（途中の `%` など）／

### 段4・段5のあとで直した、段1〜3のレビューの残り

- **状態の読み直しのログ**（`focas_client.py`）: 2秒ごとの `status`・`alarms` は、成功したときは `focas_helper.log` にも画面の記録にも書かない。
  **失敗（時間切れ・接続切れ・戻り値が 0 以外）は必ず書く**（読み直しの命令でも `→ 命令` と `× 命令 …` を書く）。ほかの命令は今までどおり。
- **赤い文**（`FocasDialog`）: 赤い文を消すのは「**読み直し（2秒ごと）の失敗で出た文**が、次の読み直しで接続が戻ったとき」だけ。
  利用者が押した操作（自己診断・控えなど）の失敗の文は、**次の操作を始めるまで残す**（読み直しが成功しても消さない）。
  `FocasWriteDialog` も同じ作り。
- **接続の時間切れ設定**: 設定 `focas_timeout` が 0 以下・数でないときは、**画面・クライアント・ヘルパーのどれでも既定の 10 秒**
  （`focas_client.connect_timeout`）。以前は、画面が 0 をそのままヘルパーへ渡し、クライアントは 1 秒に直していて、ずれていた。

### 実機で確かめないと決まらないこと（段4・段5）

- バイト型・ラベルなし以外の型（ビット／ワード／2ワード／実数／軸型／主軸型）の `cnc_wrparam` の**構造体と長さ**（設計 §12-B）。
  それまで画面は「確認済みでない型」として書かせない。偽物の機械は仕様の知識で作ったもの。
- 実数の「値と桁数」の形（`<hhii` 長さ12）。実数を書くときの桁数は、書く直前に機械から読んだ値を使う。
- 書込の途中の PW0000 の見え方（種類1・番号0 で来るか）。見つけられなかったときの手動の「電源を入れ直すので待つ」ボタンは**まだ無い**（段6）。
- 運転中・一時停止・非常停止のときの `statinfo` の数値（設計 §12-A3）。書ける状態の判定の土台なので、実機で読んで確かめる。
- 書込のモード（MDI・編集など）の条件。画面はモードでは止めず、戻り値 12（EW_MODE）が出たらそのまま理由に出す。
- `cnc_wrparam` が PWE OFF のときに返す値（7 か。設計 §12-B6）。
- 書込の直後の読み戻しが必ず合うか／丸ごと吸い出しで「書いていないのに変わった番号」がどれだけ出るか（積算カウンタ 6753・6754 など）。
